## 0. 四种布局打法(按场景选,别一把梭)

| 打法 | 适用 | 实证 |
|---|---|---|
| **A. 模板复制** | 重复单元阵列(N 路相同通道) | 用户手摆 1~2 组 → 反推「角色→(dx,dy,rot)」模板 → 程序等距复制。复制出的各组与模板逐位一致、严格等距 |
| **B. 构造式(按 datasheet 布局图)** | 电源功率级(Buck/Boost/LDO) | 按 IC 数据手册 Layout Example **直接算坐标**,不搜索。按 TPS54360 §10 Figure 52 摆一个降压组,一次成型 |
| **C. 槽位穷举** | 小信号件放进固定行/列槽位 | 例:两行×6 槽放 5 件,全排列×旋转 ≈ 240 万组合暴力求解,几十秒出全局最优 |
| **D. 退火搜索** | 无参考、无模板的探索 | ⚠️ **最后才用**,且必须带全约束(丝印/实体/热环路/朝向),否则必出"假最优"(见 §4 E1) |

> 🔴 顺序:**先找参考(datasheet 布局图 > 用户已验证布局 > 应用笔记),再选打法**。
> 有权威图就构造,有重复单元就复制,只剩自由件才搜索。

## 1. 数据获取层(EasyEDA Pro API 读 PCB 的正解)

### 1.1 🔴 焊盘→器件归属:用 primitiveId 前缀,不许用"就近"

```js
// 焊盘全局 id = 器件 primitiveId + 局部脚 id:如 '<16位hex>' + 'e6'
const own={};
for(const c of comps) for(const p of (c.pads||[])) own[c.primitiveId + p.primitiveId] = c.designator;
const pads=await eda.pcb_PrimitivePad.getAll();
// pads[i] → own[pads[i].primitiveId] 即所属器件,100% 精确
```
> 实证:就近法把 SOP-8 的外圈脚认给了隔壁 0805(SOP-8 只剩 6 脚、隔壁电阻多出 1 脚),
> 密排后必错。`c.pads` 只有 `{primitiveId, net, padNumber}`,**没有坐标**——几何必须从
> `pcb_PrimitivePad.getAll()` 拿(`p.pad = ["RECT", w, h, r]`,注意 w/h 可能为 null)。

### 1.2 🔴🔴 走线/过孔:字段名是 `layer` 不是 `layerId` —— 我的安全断言曾形同虚设

```js
const lines = await eda.pcb_PrimitiveLine.getAll();
// 字段:{net, layer, startX, startY, endX, endY, lineWidth, primitiveLock, primitiveId}
//                ^^^^^ API 对象字段;原生源记录的 layerId 是另一种表示
const vias  = await eda.pcb_PrimitiveVia.getAll();
// 字段:{net, x, y, holeDiameter, diameter, viaType, ...}

// 创建(签名已核对官方 easyeda-api skill 包里的 references/classes/PCB_PrimitiveLine.md)
await eda.pcb_PrimitiveLine.create(net, layer, x1, y1, x2, y2, lineWidth, primitiveLock);
await eda.pcb_PrimitiveVia.create(net, x, y, holeDiameter, diameter, viaType, null, null, false);
```

🔴 **血的教训**:我全程用
`lines.filter(l => l.layerId===1 || l.layerId===2).length === 0`
当作"尚未布线,可以移动器件"的写前断言。**`layerId` 在线对象上是 `undefined`,
所以哪怕板上已有几十根走线,这个断言照样返回 0 并放行。**
只因为在此之前 `lines.length` 恰好真的是 0,才没酿成事故。

**正解（2026-09-11 与 2026-09-27 实证合并，工具手册 #70）**：不能用 lines.length 判断是否已布线；封装可能返回丝印/文档线。先核实当前板的完整铜层集合及 layer 字段，再查铜层或带网名的线。四层板实测铜层为 1 / 2 / 15 / 16，不能将其硬套到其它层叠；TF 座这类封装自带的十几根线能读出层 3 / 13（丝印 / 文档层），正好拿来当过滤条件的自测样本。
```js
const copperLayers = new Set(verifiedCopperLayerIds);
if (!copperLayers.size || lines.some(l => !verifiedAllLayerIds.includes(l.layer))) throw Error('层信息未核实');
if (lines.some(l => copperLayers.has(l.layer) || l.net)) return {ABORT:'已有铜走线,禁止移动器件'};
// 弧 pcb_PrimitiveArc 同样查；还需检查 Via、铜层 Polyline 等布线图元。
```
> 这只是 LINE 的检查;还需核对 Via、铜层 Polyline/Arc 等现有布线图元,未知图元应中止。证据见本册 §1.4（原工具手册 §1.8）与 §2.8。
> **通用教训:凡是"过滤后计数==0 就放行"的安全断言,必须先验证过滤条件本身有效。**
> 判据:写断言时先跑一次**故意应该命中**的样本,确认它真的能命中。

- 板框不在 `pcb_PrimitiveLine`(那里通常 0 根);2026-07-31 时靠器件占位反推可用区。后来已验证板框是层 11(`BOARD_OUTLINE`)的 Polyline,写法与回读见下文 2026-09-13 / 09-27 补证。

### 1.3 🔴 丝印与实体包络:优先读真实图形,模型作补充

**2026-09-11 与 2026-09-27 实证合并（工具手册 #69、#70）**：Line.getAll() 能读到部分封装内部 LINE，坐标已转到板上；不同封装返回范围不同，不能把返回 0 当成没有丝印，也不能把非零当成完整外形。复合 Fill 还须查源文件（工具手册 §1.8）。

pcb_Primitive.getPrimitivesBBox([id]) 可读文字/组件包围框，已用于丝印检查，但组件框按绝对坐标轴对齐。斜放件不能用该框反推局部包络；优先使用同封装在 0 / 90 / 180 / 270 度时的读数，再结合实际位姿。不能为取框移动已经布线的器件。

检查顺序：真实焊盘与可见图形 → 工程导出的封装 PAD/POLY 与位姿变换 → 数据手册实体尺寸。丝印不等于实体外形，TF 卡投影不证明装配高度安全。未知包络不能记作 0；下表仅是历史布局的保守估算（半尺寸，mil，含当时 12 / 14 mil 余量），新物料须重新核实：

| 封装 | 半尺寸(x,y) | 注意 |
|---|---|---|
| 0805 R | (74, 41) | 焊盘主导 |
| 0805 C | (79, 41) | |
| 1206 C | (104, 48) | |
| 1210 C | (96, 62) | |
| 1812 保险 | (123, 84) | |
| SOT-23-3 | (68, 60) | |
| SMA 二极管 | (138, 65) | **实体比焊盘窄、比焊盘矮胖**,y 用实体 |
| 7.3×6.8 电感 | (156, 148) | 🔴 **实体主导**:焊盘 y 半只有 69,实体 134 |
| 10×10 电解 | (215, 210) | 🔴 焊盘 x 半 89,实体 197 —— **差 2.4 倍** |
| KF2510-4P | x=(-205..205), y=(-720..100) | 🔴 **不对称**:实体朝板边伸 720 |
| SOIC-8 | (98, 163) | 焊盘行主导 y |

> 🔴 **电感/二极管/电解/连接器 = 实体主导型**,只按焊盘算必然把别的件塞进它肚子里。
> **反标定法**:拿一版用户目视确认过的布局,量「中心距 − 双方焊盘范围」反推实体外延
> (KF2510 的 −720/+100 就是这么标出来的)。

### 1.4 PCB 侧 API 实测（原《EDA工具手册》§1.8，2026-09-27 原样搬入）

> 原标题：1.8 PCB 侧 API 实测(2026-09-10/11/12,在一块四层板上逐项实测;实测记录未公开)
> 本节里的坑编号（①～#75）和 § 号，除特别写明的，都指《EDA工具手册》。

**持久化:内存 ≠ 磁盘,保存重开才是验收**
- 🔴 **`Via.modify` 内存读回已变、持久化未变**:两孔 modify 后 getAll 是新坐标,依赖线也是新端点;保存/关闭/重开后**孔回旧坐标、线保持新端点 → 断线**。原生 DRC 用旧孔心、铺铜按新孔心,可报假/真混合短路。修法:**明确 delete 旧孔,按同 net/孔径/目标位置 create**,再保存/重开验证。
- **写操作报错不等于整批回滚,但抛异常批次里"已存在"的图元也可能只是缓存**(两次记录合成一条):多层 Pour 第二个失败,Top 在 getAll 里、save 返回 true,**保存重开后 Top 丢失**,其它三层在。重试前 getAll 盘点只能决定"补什么",**以保存重开后的持久态核验**才能决定"补够了没",不能凭 getAll 当磁盘事实。
- 保存重开会规范化小数坐标、270°→−90°、焊盘 ±π、**交换 LINE 起终点**、隐藏属性 X/Y;比较物理位置用容差 + 角度模 360 + 端点无向互换。不能把所有 JSON 差异一律认定为用户移动,也不能忽略真实变化。
- `setDocumentSource` 追加封装 POLY 返回 false、临时回读有、保存重开后没有——**不能凭 source 回显或 save=true 判成功**;原生 `pcb_PrimitiveLine.create` 可持久化;`pcb_PrimitiveArc.create` 返回对象却不在 getAll/source 里,改 `pcb_MathPolygon.createPolygon([x,y,'ARC',angle,x2,y2])`+`pcb_PrimitivePolyline.create` 圆弧才持久化(那次是板框层;**铜层圆弧走线** 2026-10-08 实测 `Arc.create` 可持久化,见本节「铜层圆弧走线」条、工具手册坑 #83)。
- 新放件的 API 状态、画布截图、保存后重开状态可能不同步;**不要用截图作唯一证据**。PCB 报 Netlist Error 时**不要预设是"旧缓存、重开就消"**——09-10 那次重开消失时同时发生了原理图属性同步,单因未证;后来同类报错重开不消,按 Unique ID 比原生属性才找到 Channel ID 为空(见下「封装与换件」)。

**字段与单位**
- `pcb_PrimitivePad.getAll()` 的 `pad.rotation` 是**弧度**;`component.rotation` 是**度**。几何避让必须区分。
- `IPCB_PrimitivePoured` 填充 path 数值是 **0.254mm 内部单位**(例:36mm ≈ 141.732),与线/孔 API 的 mil 不同。
- PCB 页 `Line.getAll()` 会返回**封装内部的原生 LINE**(ID = 组件 primitiveId + 局部 ID,坐标已全局化);统计铜走线必须按铜层筛选,不能把丝印/文档线计为布线。
- **2026-09-11 单次实测(EDA 3.2.149.88089769)**:同网近重合旧线旁执行 `Line.create`,返回4新ID但铜线仅增2,另2旧ID自动消失。须独立比对原ID/几何;cleanup按当前目标ID删,不能按返回数推净增量。不可泛化到所有相交线。
- **同日同版本单次样本**:`Line.create` 返回请求坐标,独立 `getAll` 已将新线X对齐附近同网支线,偏移约0.1mm;保存前即发生,**不是Via持久化缺陷**。属原生端点/同网吸附现象,根因未明,不能归因网格开关。线孔对齐按实际回读核验。
- **2026-09-12 单次原生拆线样本**:1条0.30mm长线跨6个同网焊盘,返回1个ID,独立回读变为相邻焊盘间5段且返回ID不存在;拆线当次旧元件/焊盘/线/孔均不变,初次回读5段与请求线的铜覆盖对称差为0,5组连接及净距检查通过。分批工具因数量不符保守停止是**待复核,不是电气失败;不得重放**。独立核对覆盖、网络、净距后,以新snapshot/网表建立新run,只补确认缺失图元;不能把1→5推广到所有create。随后新基线续跑并完成本批局部修改,**保存→关闭→重开→独立回读/原生DRC已验证**:原5段仍在(线宽按存储精度规范化),总项目Protel2网表仅排序外层列表后SHA不变;原生DRC无Clearance项,但仍有大量未布通(Connection)项,**仍未全板布通或制造放行**。
- via 请求 0.3/0.6mm 实际 readback 12/24mil(0.3048/0.6096mm);**预布线几何取回读尺寸,新计划直接写 12/24mil**,不按请求尺寸检查。2026-09-12 再次实测:写入请求与 create 返回仍是 11.811/23.622mil,独立 snapshot 变为12/24mil;完整字段门禁因 `holeDiameter/diameter` 不一致保守停止并留下 `BLOCKED.json`,**没有删阻断、没有重放,也不放宽门禁**。随后按实际12/24重新验收并完成保存→关闭→重开:两孔仍为12/24mil,目标连接保持连通,原生 DRC 无 Clearance 项;前后两批二十多条线仅发生坐标/线宽存储精度规范化,独立审计全部差值≤0.00005mil,孔径未回退。**这只证明本次有限样本,不能推断所有 `Via.create` 都必然按同样方式量化。**
- **填充 / 禁布区可以直接写圆弧(2026-10-08 实测)**:`pcb_MathPolygon.createPolygon([x,y,'L',x,y,…,'ARC',角度,终点x,终点y,'L',…])` 交给 `pcb_PrimitiveFill.modify(id,{complexPolygon})` 或 `pcb_PrimitiveRegion.modify(id,{complexPolygon})`;角度正 = 逆时针、负 = 顺时针(y 向上),圆弧之后再接直线要重新写 `'L'`。保存 → 关闭 → 重开后按几何比(多边形对称差)为 0,圆弧都在。做法见本册 §3.9。
- **铜层圆弧走线(2026-10-08 实测)**:`pcb_PrimitiveArc.create(net, layer, 起点x, 起点y, 终点x, 终点y, 角度, 线宽)` 在顶 / 底铜层建圆弧走线,getAll 和文档源码里都有,保存 → 关闭 → 重开后仍在,参与 DRC 和铺铜避让;角度正 = 逆时针(y 向上),与多边形 `'ARC'` 同一约定。
  - `get()` / `getAll()` 读回的圆弧坐标只到 0.1mil、角度取整;源码(`sys_FileManager.getDocumentSource()` 里的 `ARC` 记录)存 4 位小数,`getPrimitivesBBox` 也是全精度 → 精确核对读源码,别拿 getter 按 0.01mil 比。
  - 不跨象限的小圆弧(如 45° 弯、一头沿坐标轴)两种鼓向的包围盒完全一样,包围盒验不了方向:用 `pcb_Document.getPrimitivesInRegion(左, 右, 上, 下, false)` 在计划弧中点、镜像弧中点各框 ±1mil,前者框到、后者框不到才对;或重建铺铜后看铺铜让出来的形状。
  - `getPrimitivesInRegion` 框到某些多边形焊盘附近会抛「单多边形验证不通过」→ try/catch;查询和写操作放在同一次调用里时,抛错前的写已经生效,先回读再决定补记账还是回退,别重放。
  - 只把线改短(新端点落在原线上)的 `Line.modify` 不会触发自动拆线 / 并线(工具手册坑 #82 只在改出交叉时出现)。做法见本册 §3.10。
- **`Fill.create` 建点列多边形的三个坑(2026-10-08 实测,工具手册坑 #84)**:① 点列 `[x, y, 'L', …]` **必须首尾闭合**(起点在末尾再写一遍),否则不论铜层带网络还是丝印 / 阻焊层,一律报「无法创建填充图元,可能是传入的参数不正确」;`['R', x, y, 宽, 高, 旋转, 圆角]` 矩形格式不受影响。② 复杂多边形的多条子路径**按非零环绕**填充:洞必须和外轮廓反向(外逆时针、洞顺时针),同向的洞会被填实;存盘后 EDA 会把所有环整体翻向,核对只看「洞和直接包着它的环是否反向」。③ 带多条子路径的填充会让 `getPrimitivesInRegion` 抛「单多边形验证不通过」,不能拿框选核洞。另:API 新建的字和填充,画布 / 截图里看不到,保存 → 关闭 → 重开后才显示,核对靠回读和源码。
- `Fill.create/modify` + `createComplexPolygon` 已实测可把离散图形与镂空做成一个可整体选中的 Fill。保存重开后 `Fill.getAll` 的 `complexPolygon` 只包装第一个子轮廓,源 `FILL.path` 才完整;须按 ID 比较完整 path,**禁止拿截断 getter 回写**。2026-09-11 Logo 实证与配方见本册 §2.8。
- 符号源文件 `PIN.rotation` 指向符号内部,API `getAllPinsByPrimitiveId` 的 rotation 向外,相差 180°;换件比较新旧符号先规范化。Protel `PARTTYPE` 可能含库后缀(`_C15850`),核完整料号用 `Manufacturer Part` 字段。

**封装与换件**
- 工程内封装:`dmt_EditorControl.openLibraryDocument(projectUuid,'4',footprintUuid)`(先断言工程)→ `getDocumentSource` → 按 PAD.id 保留 num/net 改坐标 → `setDocumentSource` → `pcb_Document.save(footprintUuid)`;保存后板上引用自动更新,**无需 importChanges**。`lib_Footprint.openInEditor(id,'project')` 失败。
- PCB 组件**不能 modify 换封装**(当次客户端结论,不作全版本断言);逐件 delete/create 并从最终原理图恢复 Unique ID、真实库 UUID,按 padNumber 恢复 net。焊盘归属用 `primitiveId + 局部 padId`,不用坐标猜。
- 换件后 PCB 报 1 个 Netlist Error 且重开不消失:分别导 `pcb_Net.getNetlist('JLCEDA')` 与 `sch_ManufactureData.getNetlistFile(...,'JLCEDA')` 按 Unique ID 比原生 props——差异是新件 **Channel ID 为空**;补相同 Channel ID(普通 OtherProperty,滤掉引用键)即消。**不要全局忽略 Netlist Error,也无需整板 importChanges。**
- `pcb_Net.getNetlist('Protel2')` **返回字符串列表时**,重开后完整文本可能交换数组顺序;先验全文集合一致,再仅规范化外层顺序做 hash。**这种语义规范化只用于该多文本导出形态,不得替换 `getNetlistFile()` 单文件的原始字节 SHA 门禁**(§6.4)。
- **2026-09-12 重连后返回类型实测**:前批为2项字符串列表,当前为单个字符串,逐字等于旧列表[1];旧[0]是同一工程里另一块参考板的网表。因此只能证明该板文本未变,**不能把单板子集冒充多板全集**。必须记录并按实际 `string`/`list[string]` 类型冻结比较:**严禁 `sorted(string)` 将正文按字符排序**;单字符串保留全文顺序,列表仅可按上条处理外层。类型变化先重新核对作用域、导出范围及原始成员,同步新基线,不可静默包成单元素列表继续旧集合验收。**与打开标签数量的因果关系未验证**。

**铺铜、DRC、规则**
- **差分对规则**(2026-10-08 实测):`pcb_Drc.getAllDifferentialPairs()` 列出 `{name, positiveNet, negativeNet}`,`deleteDifferentialPair(name)` 删除,保存重开后仍为空;删前把定义存下来,要恢复用 `createDifferentialPair(name, 正网, 负网)`。电流采样电阻两端的开尔文采样线这类本来就不等长的线,不该定义成差分对,否则 DRC 永远报长度差。
- `pcb_PrimitivePour.create` 文档写 IPCB_Polygon,当前客户端传 `createPolygon` 失败、`createComplexPolygon` 成功。**create 仅边框,save 后仍 0 个 Poured**;`Shift+B`(getShortcutKeys 确认"重建所有铺铜")或实例方法 `await pour.rebuildCopperRegion()`(SDK 0.2.53 实测可用;随官方 skill 分发的接口文档未列)后才生成。
- 🔴 **布线/过孔变更后必须重建铺铜再跑 DRC**:旧填充不避让新 via,会报铜皮对过孔 0mm"短路";重建后消失。**不能删正确线路迁就陈旧铜皮。**
- `pcb_Drc.getCurrentRuleConfiguration()` 返回 `{config,name}` 包装;**`overwriteCurrentRuleConfiguration` 要传内层 `config`**,传包装返回 undefined 且读回原值。毫米会量化(0.6→0.5999988),比较容差 3e-6mm。
- Region 的 `NO_VIAS=3` 当前客户端不能据传参认定生效(写 `[3,5,6,7]` 原生只保存 TRACK/COPPER/FILL);NO_WIRES/NO_FILLS/NO_POURS 经实际相交面积复核生效。
- `pcb_Drc.check(true,false,true)` 回详细分类树(与原理图 ㉟ 不同);明细靠第 3 个参数 `includeVerboseError=true`,不传时按官方签名只回布尔(`false` = DRC 没通过,见本册 §3.6.5)。展开 list 递归统计叶子,分别报未布线与其它错误。原生 DRC 与独立连通算法对内部重复引脚/图元代表方式不同,**两者都要看**。
- **DRC 叉号清屏必须在真实 DRC 归档之后单独收尾**:先用 `sys_ShortcutKey.getShortcutKeys(true)` 核对当前“清除错误”映射,再由已获授权的 Computer Use 界面操作发键并观察确实清除;快捷键各人可能自配,以查到的映射为准,不要硬编码。Python 脚本只查到映射不等于已按键,公开 API 未验证有 clear 方法。执行状态按 `pending/completed/skipped` 留在项目证据,仅实际发键且观察成功可写 completed;完整清单见 `tools/PCB_ROUTING.md`“界面错误标记收尾”。
- 独立几何检查:实际 LED 丝印超出器件 body,用外形尺寸代替封装包络会漏碰撞,应从 epro2 封装 PAD/POLY 重算并查同面与跨面 PTH。

**DSN / Freerouting**
- `getDsnFile` 成功但**不等于原样保留手布对象**:所有 physical pads 合在一个 component,via/禁布区导成伪 pad,wiring 段数比实际 line 少了约十条,层写 1/2 但 structure 用 TopLayer/BottomLayer,via0 有同名不同尺寸定义。**必须与同时保存的 PCB JSON 逐项核对**,不能直接丢给路由器再覆盖工程。DSN 数值按 mil、SES 按 resolution 声明读。官方 Freerouting 1.9.0(Java17)可解析;`type protect` 在 SES 保留、`type fix` 省略,导回需对象比对确认手布保护。

### 2.2 Buck(非同步,如 TPS54360)—— TI Figure 52 构造式模板

来源:[TPS54360 datasheet §10](https://www.ti.com/lit/ds/symlink/tps54360.pdf)(已通读原文)、
[ROHM 布局应用笔记](https://fscdn.rohm.com/en/products/databook/applinote/ic/power/switching_regulator/converter_pcb_layout_appli-e.pdf)、
[ADI AN-136](https://www.analog.com/en/resources/app-notes/an-136.html)。

```
        ┌── 顶层地走廊(Cin地 ↔ EP ↔ D阳极 ↔ 输出电容地,连续铜)──┐
 Cin(竖:VIN下/GND上) [IC rot 使 VIN/BOOT 在左、SW/FB 在右] D(竖:SW下/GND上) L(横) 输出电容列(竖,VOUT 脚彼此对齐)
        RT 贴左下引脚                     底部小信号带(两行槽位):COMP 网、FB 分压
```
- 硬规矩:**Cin、续流管与 IC 同层且最近**;SW 节点铜面积最小;RT/FB/COMP 远离 SW、贴各自引脚;
  FB 分压两只挨着,VOUT 感测尾巴可以长(细线)。
- 达标数值(一个按此模板摆的降压组实测,作量级参考):热环路三边约 130~150 mil;SW 链约 130+120 mil;小信号 90~260 mil;整组约 34×11mm。
- 🔴 SO-8 类封装 VIN 与 SW 分居两侧,Cin地↔D阳极的回路**必须靠顶层地走廊闭合**——
  走廊(约 y+120..+300)只许进 GND 脚,BOOT 电容横在 IC 顶时要给走廊留 ≥100 mil 连续宽度。
- 各拓扑开通/关断是**两条路径**,禁写成一条"输入电容—IC—电感"串联链:热环路是两条路径之间**电流突变的那一圈**
  (Buck = 输入电容→上管→续流管→回输入电容地;Boost = 开关管→肖特基→输出电容,§2.4)。
  写成一条串联链,真正该贴死的那一圈就从描述里消失了 —— 设计文档这样写过,连续几轮审查才纠正过来。

### 2.3 摆放通用四规(与工具手册 §1.7.9 原理图摆放四规同源,PCB 同样适用)

① 多向引脚器件(MOS/SOT-23)放功能块顶/底,不夹在两脚件行中间;
② 用户丢来的器件是"料"不是"位置";成对器件相邻;
③ 同类件统一姿势(全横或全竖);
④ 间距靠错行解决,不靠拉长连线。

### 2.7 🔴 为「可调试性」而设计(2026-08-02 首板 bring-up 血泪)

一块**功能全对但没法调试**的板子,会让首板调试从 2 小时变成 2 天。实证:某板首版
一个指示灯都没有,一整天的排查里至少一半时间花在"这一段到底通没通"上。

**画板时必须留的四类东西:**

| 类别 | 具体 | 为什么 |
|---|---|---|
| **① 指示灯** | MCU 心跳、各电源轨、关键芯片的状态灯 | **MCU 心跳灯最值钱** —— 一眼分清"芯片在重启"和"只有 USB 在闪";这两种现象在电脑上看完全一样 |
| **② 白给的灯别浪费** | 很多芯片/连接器自带 LED 驱动 | 例:不少接口芯片有专为状态指示设计的 LED 驱动脚,带灯的网口座有 link/act 灯 —— **画板时顺手接上,别悬空**;接之前按手册核对每个脚的功能 |
| **③ DNP 焊盘** | 晶振的负载电容位/反馈电阻位、关键节点的分压位 | 不是电路需要,是**调试余地**。某板首版晶振周边一个焊盘都没留,想飞个件试只能拿细线搭在晶振脚上 |
| **④ 测试点** | 各电源轨、高阻节点、复位/使能脚 | 0.5mm 裸铜点即可 |

**有极性器件的丝印要加粗到"扫一眼就能发现反了"** —— 库自带的极性标很细,贴完被本体盖住就看不见。
某板首版就因此有极性件反装了没人发现,一直到上电才暴露。

> **判据**:画完板问自己一句 ——「**如果它上电没反应,我第一步能看什么?**」
> 答不上来,就该加灯或测试点。

**ESD / TVS 阵列走直通铜皮**(2026-10-07):信号铜皮从连接器经阵列焊盘直通到芯片(例:USBLC6 的 1↔6、3↔4 两对焊盘之间连铜),
**拆掉阵列线路仍然通**。怀疑阵列有问题时,能靠「拆掉它看还通不通」排查,就靠这个;改版照样这么走。
改版时阵列某个焊盘换了网,要回头清掉旧版留下的那段线和过孔,别让旧网的铜还挂在这个焊盘上。

### 2.8 接口、TF 卡与 Logo 丝印整理(2026-09-11 已验证)

| 随座子移动的图形 | 元件专属外形写入**工程内该封装**,不要只在 PCB 上散放线段。验收看导出工程内图元归属与保存重开结果;在未布线且获准的样件上可临时平移/旋转后恢复,检查包围框随动。已布线板不为验证图形而移动座子。 |
| 白色参考与制造丝印 | 看图层 ID/用途,不只看编辑器颜色。当前实例顶/底丝印为 3/4,文档参考为 13;颜色可自定义。机械参考隐藏后仍须用于卡片投影、插拔及高度核查;制造验收还须核对实际导出的丝印层。 |
| 多片 Logo 整体移动 | 将矢量外轮廓、内孔和字形制作成**单个复合 Fill**,标志和名称可作为一件;需独立调整的日期另做对象。本次 `createComplexPolygon` + `Fill.create/modify` 已持久化验证,不依赖通用 Group API。文字转轮廓后不再是可改字的文本,保留原 SVG/文字内容以便重做。完整回读限制见工具手册 §1.8。 |

**检查图形的实际面积,不只查中心点**:同面贴片焊盘与跨面通孔都参加避让;文字用原生包围框作保守检查,线/圆弧要包含笔画半宽。另查板边、其它文字、相邻器件实体,屏幕/卡片还需装配高度。净空数值按实际板厂工艺设定,不能把“这一版无相交”写成可制造。

**脚本复用(实测记录未公开)**:做这类整理的脚本(位号归一、脚位标签、封装加图形、Logo 落位及各自的回读校验)往往写死了某块板的坐标和动作分支,**不得直接套跑到当前板或其它项目**;提炼通用 helper 时先参数化、加作用域/变更检测和独立回读门禁。

## 3. 标准工作流(端到端)

```
1 读数:全器件 + 焊盘(primitiveId 归属)→ alldata.json
2 选打法(§0)→ 产出「局部坐标 plan」
3 组内自检:丝印零重叠(§1.3 模型)+ 关键网距离表
4 锚点搜索:对全板扫无冲突落位(净空 ≥40 mil),取离目标区最近者
5 写前三断言:目标文档 uuid ✓ / 铜线==0 ✓ / 位号齐 ✓ → setState 批量落位 → save(uuid)
6 回读验证:逐网焊盘距离表 + DRC 按组过滤 == 0 + 与模板逐位 diff
7 用户目视 → 用户修正后【重新读数】并把差值回填模型(反标定)
```

### 3.1 验证红线

- 🔴 **铜线 > 0(用户开始布线)后,永不移动任何器件** —— 每次写前断言:铜层(含内层)或带网名的线、弧都是 0(§1.2 / 工具手册 #70),不能只看 `lines.length`。
  **唯一例外**:用户明确要求「连线一起整体挪」(接口坐标取整、对外壳等),按 §3.8 把器件和连通的铜一起平移。
- 🔴 用户改过布局后必做**逐网 diff**:无极性件(陶瓷电容)脚对调=无害;
  **有极性件(电解/二极管/LED)对调=致命**,同样的 diff 结论完全相反。
- 数字比人工好太多(如线长砍半)→ **先怀疑约束漏了,不是庆祝**(§4 E1)。

### 3.2 小批修改的分级验收(2026-09-11 用户偏好与实证边界)

**共享离线工具**:[pcb_route_diff.py 用法与验收](../tools/audit/README.md)。比较 before/after 与可选 create 返回,输出对象增删/几何差异及吸附候选;只读快照、不连 EDA,拆线/换 ID 不自动判坏。

**共享分批工具**:[pcb_route_batch.py 指南](../tools/PCB_ROUTING.md)。默认 dry-run,显式 `--apply-one` 才追加,`--checkpoint` 分开保存/回读/DRC;不主动删除或修改旧图元。当前保守门禁遇到与预期不符的原生拆线、改 ID 或吸附会停止,须结合 `pcb_route_diff` 与实际铜覆盖复核,**停止不等于电气失败**。2026-09-12 已完成首个实板小批次(11 线+3 孔)的完整 apply/checkpoint 验证,旧四类图元不变、无坐标偏移;具体证据及过孔 metadata/剩余 DRC 边界见指南。仅此单批通过,不扩大为其它板型或异常恢复均已验证,也不等于全板 DRC/云端持久化通过。

1. 以本轮实时对象为基线,保留焊盘/位号/身份/走线/过孔/可见文字与网表等必要证据;用户中途手调后重新读数,旧快照不能证明最新布局。较大变更前保存完整工程备份。
2. **常规小批布线:保存 → 独立调用回读 → 原生 DRC 即可,不必逐批关闭重开。** 回读新增及受影响对象的层/网络/宽度/端点;丝印或封装修改还须核对完整轮廓、原 PAD/引脚网络和图形净空。
3. **动作较大、API 异常或持久化存疑时,保存、关闭重开再逐项核对。** 工具手册 §1.8 已证实 `Via.modify` 可能重开回退、异常 Pour 批次可能只有缓存记录;命中这些条件不得省掉专门验证。云端实时保存不等于所有 API 都无缓存/持久化风险。允许微小浮点规范化、角度等价及 LINE 端点交换,不能放过实际位置、尺寸、层或网络变化。
4. 较大变更或阶段收尾时,用完整工程逐文档/记录对账,确认差异只落在授权范围;常规小批无需每次重新导出全工程。多个板共用工程时,只比当前页不能证明其它板未变。网表比较遵守工具手册 §1.8 的导出形态边界。
5. 改动影响铜避让时重建现有铺铜,再做原生 DRC 并单列本轮相关错误与全板剩余项。**清除临时错误标记是可选的**:不影响观察就保留,不能为清标记阻塞布线或反复耗时定位。需要清理时先保存 DRC 结果,再清显示;清标记不等于修复错误。原生面板“清除错误”及用户配置的快捷键均已实测可用,无需重开或改规则;优先用 `sys_ShortcutKey.getShortcutKeys(true)` 核对当前映射后再发原生按键,**快捷键以你环境里查到的映射为准(各人可能自配,不要硬编码,不是软件默认键)**。按钮回退须重新读取窗口/截图定位。公开 `PCB_Drc` 参考未见 clear 方法,不能虚构 API。API 成功、单张截图、零文字重叠都不能单独代替所需证据。

### 2.4 Boost 与 Buck 的输入电容优先级相反(2026-07-31,升压组实战)

- **Buck**:输入电流是方波 → **输入电容在热环路里,必须贴死**(§2.2)。
- **Boost**:电感在输入侧,输入电流连续 → **热环路 = 内部 FET + 肖特基 + 输出电容**
  (据 TPS55340 数据手册 §10.1),输入电容优先级下降,**输出陶瓷才要贴死**。
- 布不下时先保对的那头:Buck 保输入,Boost 保输出。

### 2.5 读懂用户留下的"接口朝向"暗号

用户把两颗输出大电解(竖放)的**正极(输出网)焊盘统一朝下**摆在功率区上方 ——
这是给下方同一网的输出陶瓷/二极管**留对接方向**。围绕用户锚点布局时,
**先读它们的引脚朝向再定自己的流向**,不要只看中心坐标。

### 2.6 🔴 去耦电容的目标是「它伺候的芯片引脚」,不是全网质心

2026-07-31 实战:MCU 的两颗 3.3V 去耦电容被放到了离 MCU 两千 mil 的地方 ——
因为 3.3V 网全板到处都是,按"网络质心"搜索就被拽去了板中间。

**正解**:电源网上的电容,目标钉死为**其所属芯片的电源/地引脚**(cost 只对该芯片的脚算);
信号网(晶振/REXT/CC)天然只有两三个脚,质心法才成立。
> 判据:放完后跑一遍「去耦电容 → 所属芯片电源脚」距离表,超过 ~400 mil 的都要人工过目。
>
> 配方(目标引脚驱动的自由落位):每颗小件以它的目标引脚为中心搜索,60 mil 网格 × 4 个旋转,净空作硬约束。
> 实测一次落完一个数字区的几十颗配套小件,DRC 涉组 0。

## 3.5 走线克隆(重复单元阵列,2026-07-31 实证)

用户手工布通第 1 组 → 程序克隆到其余各组,**上百根线 + 十几个过孔一次落地,通道本地网未连接 = 0**。

```
1 读模板组(第 0 组)全部走线/过孔,换算到锚点(如该组的电感)的相对坐标
2 分类:【通道本地网】每组一套、名字带组号,如 NET_A0 / NET_B0 → 克隆
        【跨通道网】各组共用,如公共电源网 → 只克隆落在锚点 ±400mil 内的段
        【外部引线】如 NET_C0(每组一根拉到主控)→ 🔴 不克隆,另一端不跟着平移
3 落靶预检:把每个端点按节距平移后,验证它仍落在【目标器件对应焊盘】内
4 逐通道 create,每次带幂等断言(目标网已有线就拒绝,防重复克隆)
5 验证:逐通道走线数必须完全相同 + 每网未连接数 == 0 + Clearance == 0
```

**位号映射公式**(`ch` = 组号):原理图按组连续编号时,各组同一角色的位号是线性式,
如 `L(n+ch)`、`R(m+4ch)`(每组 4 只电阻,系数就是 4),`n`/`m` 取模板组的起始号。
先拿模板组和另外两组的实际位号把公式验一遍,再批量套。

🔴 **手放抖动会在克隆时变成负债**:有一组当初是用户手摆的,与模板差 1~8 mil。
克隆后产生 1 个 `5.7mil vs 要求 6mil` 的间距违例(一颗芯片偏了约 5 mil 所致)。
**解法:把该组器件对齐到模板** —— 但这是布线开始后移动器件,撞 §3.1 红线:
**须用户明确授权,并先存原坐标以便回退;没有授权就只报告违例和建议的对齐量,不动。**
拿到授权后再看「**这组线是不是程序自己克隆的**」:是,移动器件只会让线更贴焊盘;
若是用户手绘的线,则绝不能动器件,改线或交给用户。

## 3.6 布线阶段的走线规矩(2026-07-31,首次进入布线)

### 3.6.1 🔴 按【阻抗】而不是按【网名】决定谁能从电感下面过

同一条模拟控制链上(例:MCU PWM → 串阻 → RC 滤波 → 某芯片的模拟设定脚),分界点是那颗串阻:

| 节点 | 阻抗 | 能否从电感下方穿 |
|---|---|---|
| `PWM`(串阻之前,MCU GPIO 直驱) | 几十欧,数字 | ✅ 可以,且后级 RC 会把 PWM 载频滤掉 |
| **`CTRL`(串阻之后,进模拟设定脚)** | **~1kΩ 量级,模拟直流** | 🔴 **绝对不许**,直接进设定脚,耦合即输出抖动 |

> **通用化:高阻模拟节点是全板最脆弱的,不是功率回路。**
> 判据不是"这根线叫什么",而是"**从它往回看的戴维南阻抗是多少 / 后面还有没有滤波**"。

### 3.6.2 电感的"骚扰能力"差一个量级,不能一刀切

| 电感(量级) | 纹波电流 × 频率 | 下方走线 |
|---|---|---|
| Boost 级(几十 µH、安培级、几百 kHz) | 纹波**零点几安** | 🔴 什么线都别走 |
| Buck 级(10µH 级、高频大电流) | 大 | 🔴 尽量避开 |
| 小电流恒流级(mH 级、百 mA 级、几十 kHz) | 纹波仅**几十 mA** | ✅ 数字线可过 |

`纹波电流 × 频率` 就是排序依据(∝ dB/dt)。**别只看"是不是电感"。**

### 3.6.3 决定耦合量的是**回路面积**,不是"离多远"

- 走**对面层**穿过(隔整个板厚)远好过同层贴边并行;
- 让该段线的正对面是**连续 GND 铜** → 回路面积最小 → 铺铜时别在这段下面把地割断;
- **垂直快速穿过**,不要沿电感边缘长距离并行。

> 同一条经验在去耦上是 §2.6 的另一面:那边是"电容→引脚"的回路,这边是"信号→回流"的回路。
> **两处的本质都是回路面积,不是直线距离。**

### 3.6.4 晶振摆放与布线(2026-07-31,一块板上两颗晶振实测)

**优先级从高到低 —— 前三条是"错了会不起振/频偏",后面是"锦上添花"。**

| 级别 | 规矩 | 为什么 |
|---|---|---|
| 🔴 必须 | **晶振本体正下方(两层)是连续 GND 铜**,任何网络的走线都不许穿过 | 晶振脚是高阻高 Q 节点,底下过线 = 直接容性耦合 |
| 🔴 必须 | 铺铜后**清掉晶振下方的孤铜/碎铜** | 一块悬空铜比没有铜更糟 —— 浮动极板,杂散电容不确定,还当耦合中继 |
| 🔴 必须 | 晶振的**两个地脚就是金属外壳**,要**实连接地**(不用热焊盘/十字花),就近打地过孔 | 十字花给屏蔽壳串了电感,屏蔽等于白做 |
| 🟠 强烈建议 | 两颗负载电容**对称贴在晶振两个信号脚旁**,且**两颗的地脚彼此靠拢、与晶振地脚共用同一小块地** | 振荡回路电流要在最小面积里闭环,不能绕整个地平面一圈 |
| 🟠 强烈建议 | 晶振周边 150mil 内**不要有任何外来网络的铜** | |
| 🟡 建议 | 两条腿尽量短且长度接近;线宽取 10~15mil(不要为了"好看"加粗) | 加粗只会增加杂散电容 |
| 🟡 建议 | 不要贴板边、不要压在**隔离铜岛的缝**上 | 例:机壳地隔离岛就在晶振附近时,晶振下方必须是系统地 |

**别被"腿有点长"吓到 —— 先算,再决定要不要返工。**
例:一根晶振输入线铜长 539mil(13.7mm),直线只要 322mil,看着很吓人。
但 2 层板 15mil 线对地约 **1.0~1.3 pF/inch**,539mil ≈ **0.6pF**;
对 `CL=18pF` 的晶体,这点杂散引起的频偏在**十几 ppm 量级**,USB2.0 高速要 ±500ppm —— 完全不是问题。
> **判据不是"看着长不长",是"折算成 pF 占 CL 的百分之几"。**
> 真正会出事的是**地不完整**和**旁边有别的信号**,不是多绕了几毫米。

**🔴 内置负载电容的芯片,外挂电容是有害的,不是"保险起见":**
例:有的芯片(如部分 USB Hub)规格书写明**已集成反馈电阻与晶振负载电容**,再外挂 20pF 会把总负载推到 CL 以上,
**降低起振裕量**。所以同一块板上可能一颗晶振没有负载电容、另一颗(配不内置负载电容的芯片)有 —— **这个不一致是设计,不是漏画**。
> 通用规矩:看到"同类器件一个有电容一个没有",**先查数据手册有没有内置**,不要照葫芦画瓢补齐。

### 3.6.5 铺铜的焊盘连接方式(直连 / 发散)—— 2026-07-31 实测

**位置不在铜皮属性里,在设计规则里:**

```
config.Plane['Copper Zone'].copperRegion.form
  ├─ singleLayerPadModel.data['1'].connectMode   // 贴片焊盘
  ├─ multiLayerPadModel .data['1'].connectMode   // 通孔焊盘(可与贴片分开设)
  └─ trackConnectModel  .data['1'].trackConnectMode
     每项还带 lineClearance / lineWidth / lineAngle —— 这三个只有「发散」才有意义
config.Plane['Plane Zone'].innerPlane            // 多层板内电层,2 层板用不上
```

| 值 | 含义 | 怎么确认的 |
|---|---|---|
| `connectMode: 0` | **发散(热焊盘/十字花)** | 用户看到的初始态 + 伴随的辐条参数 |
| `connectMode: 1` | **直连** | 用户在 GUI 里设成直连后 API 读回 = 1(实证,非推断) |

> 🔴 **绝对不许猜这个枚举**:如果真值是 `1=无连接`,一改就是**全部 GND 焊盘从铜面上断开** ——
> 而且铺完铜看上去还是一片完整的铜,DRC 未必报。这是典型的"看起来没事的板杀"。

**三个把我卡住的坑:**

1. 🔴 **`JLCPCB Capability(…)` 这几个规则配置是只读模板。**
   `overwriteCurrentRuleConfiguration()` 打上去**不报错**,但读回原值、`isSetDefault` 自动复位 `true`。
   **要改必须先切到「自定义配置」**(GUI 里改一次就会自动切过去)。
   ⚠️ 2026-09-16 客户端 3.2.149 反例:直接对模板 overwrite **自动切到「自定义配置1」并生效**(工具手册 #75①)。
   两种行为都出现过 → 不按版本记忆判断,**写完读回 `name` 和目标字段**为准。
2. **`overwriteCurrentRuleConfiguration()` 是异步的**,立即 `getCurrentRuleConfiguration()` 读回的是**旧值**。
   要 `sleep ≥1.5s`。我第一次据此判定"写入失败",其实已经写进去了 —— 又是工具手册 ⑨ 那条(写完立刻回读拿到的是上一次的状态)。
3. **`pcb_Drc.check()` 不带参数直接调,只返回 `false`,不给任何明细** —— 这不是 DRC 不能用:按官方签名,
   第 3 个参数 `includeVerboseError` 不为 `true` 时只回布尔(DRC 是否通过),`false` 就是"没通过",布线没完成时几乎必然如此。
   要明细(做门禁、按组过滤)就传 `pcb_Drc.check(true,false,true)`,返回分类树(§1.2b、§1.4)。

**单点例外走焊盘自己的 `heatWelding` 字段**(`pcb_PrimitivePad` 有 `setState_HeatWelding`):
`null` = 跟随全局规则。全板几百个焊盘默认都是 `null`。
想让个别焊盘(如晶振地脚、功率地)与全局不同,改这个字段,不要动全局规则。

**顺带一条工程取舍**(用户明确要"全部直连"时照做,但要把这一点提示给他):
通孔焊盘直连大铜面后**手工焊与返修会非常吃力**。
常见折中是 **贴片直连 + 通孔保留发散** —— 两者本来就是分开的两条规则,改一个字段的事。

### 3.6.7 🔴 隔离沟:有效宽度 = 跨越它的最窄导体,不是沟宽

铺出一条 60mil 的隔离沟很容易,**守住它很难**。只要有一根走线或过孔穿过去,
沟挖多宽都没意义 —— 因为「铜皮↔铜皮 60mil」这条规则**管不到走线和焊盘**:

| 规则格 | 典型值 |
|---|---|
| Copper/Plane Zone ↔ **Copper/Plane Zone** | 你设的隔离值(如 60mil) |
| Copper/Plane Zone ↔ **Track** | **默认 10mil** ← 漏洞在这 |
| Copper/Plane Zone ↔ **SMD/TH Pad** | **默认 10mil** ← 漏洞在这 |

**判据必须是三项机械核对,不是看沟宽:**

```js
岛内异网焊盘数 === 0 && 岛内异网走线段 === 0 && 岛内异网过孔数 === 0
```

**跨接元件的正确摆法:让隔离边界从它两脚之间穿过** ——
一脚在岛内、一脚在岛外,**唯一跨越隔离的路径就是元件本体**。
把整颗元件放进岛内、再用走线把另一个网"引"进来接它,等于自己在沟上架了座桥。

配套(§3.6.4 同源):**跨接元件自身的两脚铜面间距必须 ≥ 沟宽**,
否则元件本体又成了新的最短路径。0805 只有约 1.2mm,1206 约 2.2mm,1808 约 2.5mm。

> 顺序:布线开始 = 器件冻结(§3.1);**铺铜前先定 GND 走廊与隔离岛**,再铺。

### 3.6.8 布线与覆铜的视觉要求(2026-09-11 用户要求,非新增 API 实验)

- 新增普通走线以水平、垂直和 45° 段组成,转弯用 45° 配直线;重复单元保持一致的出口与拐角方式,减少碎线、多余转折和绕路。局部试布先保留用户已有走线,只在明确授权区域验证风格。
- 普通控制线不为形式统一过度等长,以实际时序需要为准。USB 差分和屏幕接口按实际接口速率、器件资料、时序/阻抗要求处理,不对所有接口套同一等长指标。
- 差分线优先使用原生差分布线工具,保持线距和成对转弯,并结合实际层叠/规则检查阻抗和长度要求。**此项是操作与设计要求,截至 2026-09-11 没有验证原生差分工具的 API 调用能力**,不能写成已跑通的自动化接口。
- 覆铜边界保持规整,但电气连通、连续回流、隔离净距与器件推荐布局优先;不能为了边界好看制造狭颈、孤岛或切断回流。重建后仍需按现行规则验收。

### 3.6.9 屏幕接口与四层混合信号布线(2026-09-12)

1. **先认模组外部接口，再选布线工具。** 驱动芯片支持 MIPI 不代表成品屏模组引出了 MIPI；以具体模组规格书、座子脚表与实时网表交叉核对。QSPI、SPI、I²C 是单端，不能因为“屏幕高速”就建差分对。时钟频率、边沿、器件时序和实际板长共同决定要求，不凭频率低就忽略回流，也不凭线长不同就蛇形补齐。
2. **按实际层叠找最近参考面。** 两个内层之间可能隔着厚芯板，内层信号的最近地参考常在外层；读取当前层叠和实际铺铜，不能把“走内层”当作已获得连续地参考。制造堆叠未确认时，不宣称阻抗已达标。
3. **离线方案必须合并检查。** 各网单独通过不能代替总方案通过；通孔是跨铜层障碍。以实际焊盘形状、已布线、孔径、禁布区检查净距，并检查指定引脚之间的物理连通。方案合并输出由一个执行者维护，子代理只输出独立候选，避免审查任务覆盖正在实施的计划。
4. **地参考要读重建后的 POURED。** 绘制 Pour 边界不证明有地铜；去孤岛、热焊盘、其他走线会改变实际填充。解析时处理孔洞/圆弧，校准 POURED 与线孔 API 的单位差异；采样覆盖只用于定位缺地段，不是阻抗、狭颈或回流完整性的证明。换层处结合实际可用空间补接地连接，不能只堆孤立的 GND 网络过孔。
5. **分清实施与验收。** 小批独立回读与 DRC 分开；保存/重开服从当前用户授权，脚本若内含保存须事先识别。未进行的持久化验证如实记未验证。清 DRC 显示要先归档报告，查询快捷键不等于实际按键。

上述方法已用于一次屏幕信号实板批次：单端接口判定、联合几何预检、分批写入、独立回读与原生 DRC 分别留证。具体模组、网络、坐标、数量和剩余问题属于项目证据，不作为其他工程的默认参数。

### 3.7 走线连通性自查(可复用配方,E13 的正解)

> 🔴 **适用边界(2026-07-31 被自己误报打脸后补的)**:本配方只建模
> **走线 / 过孔 / 焊盘**,**完全看不见铺铜**。
> 对「纯靠铺铜导通」的网(GND、机壳地、大电源网),它会把每个焊盘各算一个连通块,
> 报出一堆假的"断开"。
> **判据:该网走线数为 0 或远少于焊盘数时,本配方的结论一律作废**,
> 改用渲染目视或 EDA 自身的未连接报告。

EasyEDA 的 `pcb_Drc.check()` 不带参数只回一个布尔(`false` = 没通过),看不出哪条网断在哪;
传 `check(true,false,true)` 能拿到原生明细(§3.6.5、§1.4)。原生 DRC 与独立连通算法对重复引脚/图元的表示方式不同,
**两者都要看** —— 下面是独立连通检查**能跑对的最小版本:**

```js
// 节点 = 每个线端点 / 过孔 / 焊盘;边 = ①段内首尾 ②同层坐标邻近 ③过孔与通孔焊盘跨层
const N=[], seg=[], par=[];
const add=(x,y,ls,tag)=>{N.push({x:+x,y:+y,L:new Set(ls.map(Number)),tag});return N.length-1;};
for(const l of nl){ const a=add(l.startX,l.startY,[l.layer],'w'),
                    b=add(l.endX,  l.endY,  [l.layer],'w'); seg.push([a,b]); }  // ★ 记下配对
for(const v of nv) add(v.x,v.y,[1,2],'v');
for(const p of np) add(p.x,p.y, Number(p.layer)>=11 ? [1,2] : [p.layer], 位号);
for(let i=0;i<N.length;i++) par[i]=i;
for(const [a,b] of seg) uni(a,b);          // ★★ 最容易漏的一条边,漏了就恒报"断开"
for(let i=0;i<N.length;i++) for(let j=i+1;j<N.length;j++)
  if(Math.abs(N[i].x-N[j].x)<=8 && Math.abs(N[i].y-N[j].y)<=8 && 有共同层) uni(i,j);
// 所有焊盘的根 === 1 个 → 该网连通
```

三个必须知道的字段事实(全部实读,猜错就静默出错):

| 字段 | 真相 |
|---|---|
| `line.layer` | `number` 1(顶)/ 2(底) |
| `pad.layer` | `number` 1(贴片)/ **`12`(通孔件,不是 1 也不是 2)** → 要同时并进 1 层和 2 层 |
| `pad.hole` | **对象** `{type:'ROUND'\|'SLOT', diameter:…}`,**不是数字** —— `+p.hole>0` 恒为 `false`,不能拿它判通孔 |
| `pad.padType` | 全板都是 `0`,**区分不了通孔/贴片**,别用 |

坐标是浮点(如 `1234.56789012345` 这种十几位小数),但走线端点与焊盘中心**精确重合(距离 0)**,
容差取 8mil 只是为了兜手放抖动。**做完先跑双向自测再看结果。**

### 3.8 已布线的块整体平移(2026-10-07 实测:接口坐标取整)

**什么时候用**:用户明确要求把已经布了线的接口 / 模块挪到整数坐标、对齐外壳,并且「连线要一起整体挪,不要只挪端子」。这是 §3.1「布线后不动器件」的唯一例外。

1. **先问清楚动哪个方向。** 板边接口通常只动沿板边的那个坐标:改了端子到板边的距离,插头可能被板子挡住、插不进去(2026-10-07 用户提醒)。另一个方向不动,除非用户要。
2. **块按连通找,不按区域圈。** 从块内器件的焊盘出发,顺走线和过孔找,碰到块外器件的焊盘就停,记为跨界。用户常会故意留断口,方便整体挪,断口就是块的边界;按区域圈会把断口外那一段(比如通往主控的信号线)误认进来。只靠铜皮连着的过孔、填充,按位置单独认领。
3. **真正跨界的线**(一路连到块外器件)按方向拉伸:长竖线跟着横移,下一段 45° 斜线的起点重算,保持横 / 竖 / 45°。
4. **重复单元顺手归位**:按第一组做模板逐位克隆(器件、模板线、过孔、小填充),各组原有的微小抖动一起归零;每组自己特有的线跟着它连的那颗件走。
5. **执行顺序**(每块一次调用):核现值 = 计划旧值(不符就整块不动,说明有人改过)→ **删光块内线**(每删一根重读,EDA 合并出来的残段一起删)→ 挪器件 → 按新几何建线 → 过孔先建新再删旧(Via.modify 重开会回退,§1.4)→ 字、位号、填充 modify。🔴 不要逐根 modify 挪线(工具手册坑 #82)。
6. **填充(铜皮)**:接线端那一截顶点跟着挪、另一端不动,逐边检查仍是横 / 竖 / 45°,并核对焊盘四周的余量没变。
7. **离板边的距离**:挪完焊盘到板框不小于规则值(常见 0.3mm)。取整前先算:某个固定焊盘按「最近的整数」取整后,离板边只剩 0.05mm,只能取另一侧的整数。
8. **验收**:先离线模拟(所有网的连通分组不变、异网间距不变小、离板边距离);写完按几何比(合并共线段后的集合 = 计划);保存 → 关闭 → 重开 → 全板 diff,只许出现计划内的变化(隐藏属性的坐标重开会被规范化,忽略;可见位号会跟着器件走);原生 DRC 按类别和改前比。
9. **丝印跟着走,顺手对齐**:端子说明字居中到端子上方;同类的位号、说明字统一相对位置。

### 3.9 铜皮(填充)与禁布区的美化:圆角、对齐、合并(2026-10-08 实测)

**什么时候用**:布线完成后,用户嫌填充(当粗线用的铜皮)的直角 / 倒角不好看,要圆角;或者同网的几块填充互相压着,要合成一整块。

1. **合并重叠的同网填充**:同网同层、互相压着的几块,求并集(如 shapely `unary_union`),确认是一个没有洞的多边形;改其中一块为并集轮廓,删掉其余几块(先改后删,铜不断)。
   🔴 **接缝处要单独看一眼**:两块搭在一起的地方,并集轮廓常走成「之」字(外角 → 短竖边 → 小内角 → 短平台 → 斜边),只给内角倒个小圆角会像被咬了一口。按外形二选一并出预览给用户挑:内角放大成 S 形过渡,或者把缺口填平、让边直接顺到斜边上(多出的铜照样做异网间距和焊盘覆盖核查)。
2. **先对齐**:去掉几乎共线的折点(转角 <1°)、拉平 <0.1mm 的小台阶(两块填充边没对齐留下的),再把边吸到 45° 的整数倍。这些偏差都在百分之一毫米量级,但会让后面的倒角认不出来。
3. **用户画的倒角 → 相切圆弧**:倒角 = 夹在两条长边之间、两头到虚拟拐点距离相等的短边。切点就取倒角两端,直边一点不动;半径 `R = d / tan(转角/2)`(90° 拐角时 R = 倒角腿长)。
4. **其余拐角全部倒圆**(用户要「尽量都加上」时):45° 转角(长斜边两头)R1.0mm、90° 转角 R0.5mm;一条边两头的切线长(`R·tan(转角/2)`)加起来超过边长 90% 就按比例缩小半径。只改倒角、不改其它拐角时,用户会看出「有的圆有的不圆」—— 先问清楚要不要全改。
5. **核查**:凸角倒圆是削掉铜、凹角倒圆是补铜。逐块算:异网铜(线 / 焊盘 / 孔 / 别的填充)离新轮廓的最近距离不能比原来小到违规;同网焊盘被填充盖住的面积不能变少;新轮廓扫到的区域里不能有异网铜。禁布区同理(新形状多出来的那块里不能有铜)。
5b. **禁布区穿出板框的地方**:铺铜被禁布区和板框夹出一个 90° 直角。在禁布区轮廓上、穿出板框处加一个内凹圆弧:区域在板外的那段整体外移 R,到板沿后用圆弧接回原来的边(扫角 +90°,顺时针多边形里是左转),铺铜重建后跟着变圆;先确认新多出来的那一小块里没有铜、离最近的焊盘还够宽。
   🔴 **圆弧要和铺铜实际的边相切,不是和板框相切**:铺铜离板框、离禁布区都有规则间距(先从 `pcb_PrimitivePoured` 的 `pourFills[].path` 量,坐标单位是 10mil)。设铺铜离板框 c、离禁布区 g、想要的铺铜圆角 r:禁布区圆弧半径取 R = r + g,并与板框内 (c − g) 处的直线相切。只让圆弧贴着板框画,铺铜那条收缩后的直边会把圆弧截断,扫角不到 90°、和直边成角相交,看着就是个折角。改完回读铺铜,核对圆角扫角 90°、起止点正好接上两条直边。
6. **整根压在同网填充上的线**(铜面 ≥95% 被盖住、露出来那点不碰任何焊盘)可以顺手删掉;逐根删、每删一根核总数只少 1(工具手册坑 #82)。
7. **收尾**:每块铺铜各调一次 `rebuildCopperRegion()`(一块一次调用),跑原生 DRC;保存 → 关闭 → 重开,按几何(对称差)核对每块填充、禁布区,不按数组逐字比(读回会规范化)。
8. **丝印标注**(顺手的美化):`pcb_PrimitiveString.create(layer, x, y, text, fontFamily, fontSize, lineWidth, alignMode, rotation, reverse, expansion, mirror, primitiveLock)` 共 13 个参数,字体必须在字体列表里(否则抛错);
   `alignMode` 1~9 = 左上 / 左中 / 左下 / 中上 / 中心 / 中下 / 右上 / 右中 / 右下。一列说明字贴着器件左边放,用「右中」(8)、锚点 = 右边缘 + 行中心,`getPrimitivesBBox` 读回的字框右边和竖直中心正好落在锚点上。字体、字号照板上已有的说明字。

### 3.10 走线拐角改圆弧(2026-10-08 实测)

**什么时候用**:布线完成后用户要「布线也改成圆弧」(常在看过铜皮 / 禁布区圆角之后)。泪滴没有公开 API(快捷键表里只有界面命令「泪滴」,没绑键)→ 由用户在界面点(工具 → 泪滴)。顺序:**先改圆弧 → 再点泪滴 → 最后重铺铜**(泪滴贴着出焊盘那段直线生成,先点泪滴再改线会对不上)。

1. **候选拐角**:同网、同层、同线宽的两段首尾相接,该点只有这两段(T 接不改),不在焊盘 / 过孔 / 同网填充上,转角 5°~135°。线宽不同的拐弯(一段粗一段细)一条圆弧表达不了,单独列给用户定。
2. **半径**:45° 弯 R = max(1.0mm, 2×线宽),90° 弯 R = max(0.6mm, 2×线宽);切线长 `t = R·tan(转角/2)`,两段线各从拐点往回缩 t,中间接一条相切圆弧。
3. **长度预算**:一段线两头都改圆弧时,两个切线长之和 ≤ 段长 − max(10%, 2mil);接焊盘 / 过孔的那头先给泪滴留直线(出焊盘后留「焊盘短边 ×0.8,夹在 0.3~1mm」),留不出时圆弧最多吃掉出焊盘那段直线的一半;被切掉的那一截上不能有别的同网线头 / 过孔 / 焊盘(会断开)。放不下就缩半径,缩到不到线宽一半就不改(改了也看不出)。
4. **平行走线一起拐弯用同心圆**:同层、转角相同、进出方向都平行、拐点沿角平分线排开(偏离 ≤1mil)、中心距 ≤1.3mm 的**相邻**两根连成一组 —— 中间夹着别的同向拐弯就不连,跳着连会让外圈拿到很大的半径。最里面那根用标准半径,往外每根加中心距、再小 2mil(弧段间距略大于直线段,最紧处仍留在原来那段直线上)。各用同一个半径的话,外圈的弧会切向里圈,压着规则间距走的总线必然违规。
5. **间距按全部改完后的最终几何核**:每条圆弧对异网铜(线、别的圆弧、焊盘、过孔、填充、板框、禁布区)按板子现行规则表(`pcb_Drc.getCurrentRuleConfiguration()` 的 Safe Spacing)判:要么比规则多 0.3mil,要么不比原来更紧。🔴 别一律要求「规则 + 余量」:原来就压着规则走的平行线,圆弧做得再好也只能等于原间距,会被全部误杀。不够就缩半径重算,同心组整组缩,缩不动拆成单根再试。
6. **重复单元对一遍**:阵列里几何相同的拐角,各单元半径应该一样;不一样说明各单元本来走得不同,列出来,不强行统一。
7. **执行**:先备份。每个拐角一次调用:核两根线「要改的那头」还是原值 → 两根线各改短一头(只改那一头的坐标)→ `Arc.create` → 回读(线端、圆弧端点按 0.1mil 精度、包围盒、弧中点框选)。每做完一个就追加记账「圆弧 id + 两根线原端点」,回退按记账删圆弧、恢复线端。先试几个代表性的(同心组、最粗线、普通线)→ 保存重开 → 重铺铜跑 DRC → 再做全部。
8. **验收**:全部做完重建铺铜 → DRC → 保存 → 关闭 → 重开 → 按源码逐条核 → DRC 再跑;离线比改前改后:只许计划内的线端变化和新增圆弧,其它类别一字不差(重开会规范化用户之前挪过的器件坐标 / 标签偏移,分清来源);每个网络的铜连通块数不变;用重铺后的铺铜形状旁证鼓向(铺铜离每条计划圆弧都 ≥ 规则,假如圆弧是镜像的会有大量 < 规则)。
9. **报给用户**:改了多少、哪些没改及原因(太挤 / 线宽变化 / T 接 / 拐点在过孔上),附一张标了位置的图,免得被当成漏改。
10. **泪滴在哪、怎么核**:泪滴不在任何 `getAll` 里,只在文档源码的 `TEARDROP` 记录(`path` 是 mil 坐标的 L/ARC 多边形,`refs` = [线 id, 焊盘全局 id(器件 id + 焊盘局部 id)或过孔 id])—— 只看 dump 会以为板上没有泪滴。🔴 **改线前板上已有泪滴的话,改线后旧泪滴不会自己更新**,要让用户重新点一次「泪滴」:会全部重建(id 全换),挂在改过的线上的按新线形重新贴合,其余形状不变。核查按「焊盘 / 过孔 + 层 + 线」比改前改后的集合(一个不该丢),再查泪滴沿线方向有没有越过线端伸进圆弧;最后重铺铜、DRC、保存重开按源码比 id / 形状 / 挂接。

### 3.11 开窗画 / 丝印画:把图案做成阻焊开窗 + 丝印(2026-10-08 实测)

**什么时候用**:用户要在板上画图案(角色头像、Logo、漫画格),要「开窗」的金属质感。

1. **三种颜色**:阻焊本色(什么都不放)、阻焊开窗露出的铜(沉金发金;喷锡发银,大块会起伏)、丝印(白;白色阻焊时丝印是黑的)。开窗下面必须是**完整的同网铜**(一般是 GND 铺铜):下面没铜会露出基材(又一种颜色),压到别的网络会把信号铜露出来。先查范围内没有走线、过孔、焊盘和别的网络的铜,铺铜覆盖 100%。
2. **工艺余量**(按板厂规格再核):开窗和丝印之间至少 0.2 mm 暗缝(这道缝正好当线稿);丝印线宽 ≥0.15 mm、字高 ≥1 mm;所有特征 ≥0.18 mm 更稳。
3. **自己画还是映射**:简单的图标(动物、灯泡、星星)可以用贝塞尔曲线自己画;人物(尤其二次元头像)手画很容易被嫌「乱、怪、生硬」 —— 用户手上有参考图时直接映射,更快也更像。映射别人的图先确认用途(自用二创 / 商用要授权)。
4. **位图映射**:
   - 按 Lab 颜色找最近原型,把像素分成 暗 / 金属 / 白 三类(先在图上取几个代表色:线条、背景、头发、皮肤、腮红……);
   - 🔴 **背景只认从图片边缘连通过来的那一片**:动漫图的背景色常和腮红、阴影同色,纯按颜色分会在脸上挖出黑洞;
   - 中值滤波去零星误判;原图线条按缩放后的实际宽度外扩到 ≥0.18 mm;高斯平滑去 JPEG 毛刺;开运算去细碎;太小的岛和洞去掉;金属和白之间强制留出暗缝;
   - 矢量化(轮廓 + 层级)后简化约 0.01 mm;外框之类的装饰放在最上层压住图(放在下层会被图挤掉);
   - 整幅缩小和局部放大差别很大:缩得越小,线越要加粗、越失真 —— 两种裁法都出预览让用户挑。
5. **写进 PCB**:每幅图每层一块整体填充(带镂空的复杂多边形),用户可以整体选中挪动:开窗写顶层阻焊层,白色写顶层丝印层。点列首尾闭合、洞和外轮廓反向(§1.4、工具手册坑 #84)。
6. **核对**:读源码 `FILL.path` 还原几何和计划比对称差;逐个检查洞和直接包着它的环反向;保存 → 关闭 → 重开后再核一遍;DRC 和改前比;全板 diff 只许多出这几块填充。
7. **改大小 / 挪位置**(用户看了 3D 说「往右挪」「加大一点」):按新尺寸**重新映射**,不是把做好的几何拉大 —— 外框线宽、暗缝、最细特征保持原值。尺寸和位置一起搜:开窗内缩一点后仍整块落在同网铺铜里、离别的网络的铜留余量,离看得见的器件框 / 过孔 / 字留 ≥0.6 mm,取能放下的最大倍数再打个折;只做「看着空」的判断不够,铺铜下面常有一条别的网络的走线贴着边。替换时只删记账里旧那幅的填充(别的图不动),读源码确认删掉了再建新的。

### 3.12 有极性件加粗极性条、接口旁标字(2026-10-08 实测)

**什么时候用**:改板清单里有「有极性件加粗丝印极性条」(多半出过反装),或用户要在接口旁写名字(USB 之类)。

1. **阴极按网表脚名认**:读网表(EDA 里是器件的 `pinInfoMap`)的脚名 `K` / `A`、`-` / `+`,不按脚号惯例、也不按电流方向猜 —— 照功能推很容易推反。不用加的:双向 TVS(型号带 `CA` / `BI`)没有极性;SOT-23 这类三脚封装装不反;电解电容先看封装有没有印「+」和斜角;多脚的 MOS / IC 看封装自带的 1 脚圆点。
2. **先读封装自带的标记**:封装源码在工程文件里 —— `sys_FileManager.getProjectFile()` 导出的 `.epro2` 是 zip,里面的 `.epru` 是整个工程的源码,每个文档以一行 `DOCHEAD` 开头,按封装 uuid 找到 `FOOTPRINT` 那段。只有层 3(顶层丝印)会印到板上;层 13(文档层)、49(器件标识)、50(引脚焊接)都不印。画布上发橙色的小方块 / 「+」一般是丝印层的**填充**(半透明叠在红色铜上),不是别的层。
3. **放法**:
   - 两焊盘之间本来就有一根细阴极线的(SMA / SMB / SMC、SOD-123、SOD-323 常见):条放在阴极焊盘内侧、离焊盘 0.15 mm,正好盖住那根细线,看上去就是「原来的线加粗」。粗细按封装大小(SMC 约 0.6、SMA 约 0.45、SOD-123 约 0.35、SOD-323 约 0.25 mm),长度 = 本体宽 − 0.3 mm,用圆头线(端点往里缩半个线宽)。
   - 🔴 **两焊盘之间有「T」形小标记的**(贴片 LED 封装常见,对应灯珠背面的极性标):别把条放在 T 的竖线末端 —— T 会变成「工」字,分不出哪头是「一横」,照背面标记对位的人反而会装反。改成把阴极那一端的外框线(通常就是带缺角的那端)加粗:离焊盘更远,装好后露在本体外面,还能目检。
4. **写入与核对**:`pcb_PrimitiveLine.create('', 3, x1, y1, x2, y2, 线宽, false)`;离所有焊盘 ≥0.15 mm(板厂会把压到焊盘的丝印裁掉);回读坐标、线宽;保存 → 关闭 → 重开后全板 diff 只多这些线;DRC 和改前比。
5. **接口旁标字**:字体、字号照板上已有的通道号 / 位号;在接口四周找离器件框和别的字 ≥0.3 mm、离焊盘和过孔 ≥0.15 mm、离板边 ≥0.8 mm 的最近空地;建完用 `getPrimitivesBBox` 读回真实字框再核一遍,不合格当场删掉。
6. **写回自己的检查脚本时**:「出计划」的脚本别在模块顶层就读命令行参数、干活 —— 被「执行」脚本 import 时会吃掉对方的参数崩在半路(线已经建了、记账还没写)。函数放进 `main()`,执行脚本只 import 函数。
