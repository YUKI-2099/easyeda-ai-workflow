# EDA(嘉立创专业版)AI 作业通用手册 · 跨项目版 v1

> 用途:任何新硬件项目里,AI 助手在嘉立创EDA 专业版里做**原理图/PCB 编辑、电路检查、PCB 分组、BOM 整理**的通用规范,
> **以及独立审查到收敛的完整流程**(§9)。
> 本文**自包含**——不依赖任何具体项目的文档或历史记忆,拷进新项目即可用。
> 来源:多块实际板子(2026-07 起)的实战沉淀;
> 含多起事故换来的铁律,以及一次"从零画完整两块板 + 七轮 AI 互审直到冻结"的完整闭环。
> 边界:本文只装**跨项目通用**内容;某项目的电路事实、器件 UUID、板级坑 → 写进该项目自己的项目文档,不要往这里塞。

## 1. 铁律(违反必出事,每条都有事故背书)

1. 🚨 **写前双断言**:任何写操作前,脚本必须**程序性 assert**:①实时读回的当前工程 / 文档 uuid == 目标(新工具写法见工具手册 §1.6 防线 1);②件数量级/关键位号谱符合目标板。
   *打印证据给人看不算门禁——脚本必须自己拦自己。断言失败即终止,绝不"接着试试"。*
   > 血案:`doc switch` 返回成功但窗口没真切换,脚本在**另一块板**上删了元件并存盘。

2. 🚨 **`pcb import-changes` 永久拉黑**:会整板重摆(曾把几乎全部器件重摆一遍,含已锁定的接口件)。网络同步只允许逐件/逐网/逐绑定。

3. 🚨 **用户 GUI 活跃编辑时,AI 对同一文档禁写**。该时段 API 读数可能陈旧自相矛盾,不得用作终验。用户现场永远优先。

4. **只认数据,不认截图不凭记忆**:对错看检查器结果(DRC 等) + 网表成员集合。快照/画布可能陈旧或空白(渲染不跟 API 走)。

5. **检查器的"可删除"分类不可信**:零长线、dangling-wire 会把**活连接**误标为孤立线(多次实证)。**禁止批量删线**;确要删则逐根删+每删即查(浮空数/网表 diff),异常即停。
   *API 无 undo,GUI Ctrl+Z 是最后防线(API 批量删 ≈ GUI 单步)。*

6. **绑定/结构异常未排除前,禁止 `doc reload`**:reload 会先 save,把损坏状态**固化**,重开后客户端可能直接丢弃坏件。
   > 血案:参数同步误写引用键 → 绑定残缺 → reload 固化 → 十几个器件全部消失,靠重建才救回。

7. **改前快照、改后对账**:批量操作前记录关键网成员集合,操作后 diff;新增浮空/悬挂立即处理。

8. **复验必须显式指定新数据源**:脚本默认引用缓存产物(旧网表/旧快照)会得出假结论——缺省数据源应**报错**而非静默回退。

9. **布线开始后,坐标真源=用户走线**:用户动手布线起,AI 永不移动任何器件;验收口径切换为 DRC+走线完整性,bbox 重叠等摆位门禁全部作废。原理图版式同理——用户重排过,版式就归用户。

## 2. 范围与路由

- **三重范围锁**:每次操作锁「窗口ID + 父原理图UUID + 页面UUID」。窗口ID 会漂移,必须从 Bridge **实时读取**(工具手册 §0.4),严禁沿用旧 ID。
- 多窗口开同一工程时,先明确选中目标窗口再干活(工具手册 §0.4),不要靠默认。
- **多页工程**:读器件、读导线这类接口**只作用于当前激活页**;跨页核对要逐页 `openDocument(<页uuid>)` 循环(工具手册 §2.9)。
- 页面激活是**慢异步**:切页返回后要等一下 + 独立读回确认,别信返回值。
- **位号作用域 = 单板/父原理图内唯一**(两块板可以同名);合并采购 BOM 必须加板级前缀。用户 GUI 挪动会洗牌位号 → **认网名不认位号**。

### 3.1 `sch place` API 放件的两个先天缺陷 ⚠️

API 放件与 GUI 放件**不等价**,放完必须补两刀:

| 缺陷 | 现象 | 正解 |
|---|---|---|
| **参数包不抄** | 实例 `otherProperty` 是**全空模板**,而器件库记录 `lib_Device.get(uuid).property.otherProperty` 本身满值 → 显示名公式 `={Value}` / `={Manufacturer Part}` 解析成空白 | 逐件:库记录 otherProperty 为底 + 实例非空值覆盖合并 → `setState_OtherProperty(merged)` → `await done()` |
| **supplierId 填错** | 被写成子件名(如 `0805W8F1200T5E.1`)而非立创编号 → **BOM 级隐患** | 同步时连带纠正;**必须断言 `supplierId == 立创编号`** |

⚠️ **合并时必须剔除引用键**:`Footprint` / `Symbol` / `3D Model` / `Device` 这些 UUID 引用键**绝不能**写进实例 otherProperty——会顶掉正确绑定,进而(配合 reload)导致丢件。
⚠️ `sch modify --patch '{"customAttributes":{...}}'` 是**假成功**(返回 ok 但不落地),勿用。

**SOP**:API 放件 → 参数包同步 → 断言(Value 非空 + supplierId==立创编号 + fp/sym/component 绑定齐 + 引用键=0)。

**修 `supplierId` 的两种姿势**:

| | 做法 | 适用 |
|---|---|---|
| **事前预防** | `sch modify` 的 patch **一次性带全**:`designator / name / supplierId / manufacturer / manufacturerId / supplier / otherProperty / addIntoBom / addIntoPcb` | 改位号/挪坐标时 |
| **事后修复(更安全)** | `setState_SupplierId("C<立创编号数字>")` **单键写** | 已经被污染了 |

> 单键写法在**两张临时废页**上先验证过(人为构造"错误 `.1` → 正确 C 号"),
> 确认 Component / Symbol / Footprint / Manufacturer / OtherProperty 前后完全不变。
> **改法拿不准时,先在废页上验** —— 这个习惯救过一次十几件全丢的事故。

**验证纪律(这里翻过车)**:
- `sch/pcb modify` **返回 `ok=true` 不等于已落盘**。实测批量改 supplierId 首次返回成功、读回仍是旧的 `.1`。
- 可靠流程:**单件重试 → save → 立即 `list` 回读 → 重导网表核 SHA**。
- 🔴 **同页同类器件,不得因首件成功就推定整批成功** —— 必须逐件读回。

### 3.2 NC(非连接标识)打叉

`sch no-connect` CLI 命令在 EDA 3.2.149 上**失效**(`pin.setState_NoConnected` 不在 pin 代理上)。正解:

```js
const pins = await eda.sch_PrimitiveComponent.getAllPinsByPrimitiveId(pid);
const t = pins.find(p => String(p.getState_PinNumber()) === '3');
t.setState_NoConnected(true);
await t.done();
// 读回断言 t.getState_NoConnected() === true
```

> 教训:`api search` 索引把这方法标在 `sch_Netlist` 名下是**错的**,实际挂在 `sch_PrimitiveComponent`。**索引不可信,以运行时原型枚举为准**:
> `let cur=obj; while(cur&&cur!==Object.prototype){Object.getOwnPropertyNames(cur).forEach(...);cur=Object.getPrototypeOf(cur);}`

> 🔴 **打 NC 叉之前先查规格书的 pin 表:脚名叫 NC 不等于能悬空**(2026-10-07 审查实证)。
> TPS55340(HTSSOP-14)的 11 脚在符号上叫 `NC`,TI 规格书写的是 *"Reserved pin that must be connected to ground"*(图 5-2 注:connecting NC with AGND)。
> 某板首版一直把它悬空,改版审查时还按「脚名是 NC」给它打了叉,等于把错误盖了章;是独立审查员读规格书抓出来的。
> **NC 叉只打在规格书明写「不连接 / 可悬空」的脚上**,注释里写出依据。

### 3.3 输出格式与坐标系陷阱

- `sch check --json` 输出是**顶层** `{passed, summary, findings}`(**无** `result` 包裹)。`findings[].pinDetails` 带**引脚坐标**,是引脚级几何最好的来源。
- `sch netlist` / `sch snapshot` 的产物路径在响应**顶层 `artifacts[].path`**(不在 result 里)。
- `doc reload` 输出是**纯文本** `✓ reloaded`,不是 JSON——按 JSON 解析会误判成失败。
- `sch sheet-geometry` 也是纯文本;且它报的明细表(标题栏)范围**远小于实际表格**。A4 横版实测:元件要避开 **y<200 且 x>350** 的整条底带。
- **原理图 y 轴向上为正**(原点左下),明细表在"低 y"区。坐标单位 = 10mil,自动吸附。
- `sch list` 的 `components` **包含图框(sheet)和网标/网络端口(无位号)** → 统计真实器件必须过滤 `componentType=='sheet'` 与无位号项。

### 3.4 其它

- **设计规则 API 写入**:`eda.pcb_Drc.overwriteCurrentRuleConfiguration(cfg.config)` 必须传**裸 config 内容**,传 `{name,config}` 整包会**静默无效**。流程:get → 改 cfg.config 字段 → overwrite(cfg.config) → 读回验证。(规则对话框卡死时的完整旁路)
- **写接口假成功**:关键字段(锁定、layer 等)可能静默无效——读回不变时换"删除+按目标参数重建",别重试同一写法。
- **搬迁疗法**:密集区 autoconnect 卡住 → 把件搬到空旷区重接,几乎必成(仅限用户未开始布线前)。
- `lib by-lcsc --lcsc <C编号>` 比 `lib search` 稳,直接给 libraryUuid + deviceUuid。

### 3.5 从零画整份原理图踩到的坑(2026-07 实证,两块板、上百个器件,含 7 轮互审)

> **速查**:A 参数污染 ｜ B 批量静默失败 ｜ C 改网两步 ｜ D 坐标重叠 ｜ E keepout 不可信 ｜
> F 命令级坑 ｜ G delete 静默失败 ｜ H 单条假失败 ｜ I 复制进来的死端子 ｜ J 换型安全流程 ｜
> K 控制台 GBK ｜ K2 跨板位号重名 ｜ L 先拆后装的顺序 ｜ M 先查参考设计 ｜ N 开漏网单独扫

**A. supplierId 与 Value 的真实污染机理 —— 修正 §3.1 的归因**

| 操作 | supplierId | otherProperty(含 Value) |
|---|---|---|
| `sch place` | ✅ **正确的立创编号** | ⚠️ 是**空模板**(键都在、值全空) |
| `sch modify` 任意短 patch | 🔴 被污染成 `<MPN>.1` | 🔴 **整个被清空** |

- **`.1` 的来源实测**:器件记录里有 `subPartName` 字段(如 `CL10A106KP8NNNC.1`),`modify` 时被错写进 supplierId。
- **§3.1 原来写"place 时 supplierId 被写成子件名"是错的** —— place 是干净的,是 modify 污染的。这个区别很要命:放件只做一次,而**改位号/挪坐标是每颗器件都要做的**,按旧理解"放完同步一次"之后每次 modify 都会重新污染。
- **正解(实测通过)**:
  1. `modify` 的 patch **必须带上 `supplierId`**(两字段同 patch 即可,不必带全 9 个);
  2. **Value 只能走 `setState_OtherProperty`** —— `modify --patch {"value":...}` / `{"Value":...}` 都是**假成功**(ok=true 不落地);
  3. 把「补 Value + 断言」做成**幂等的固定后处理脚本**,任何改件之后跑一遍,比每次拼超长 patch 可靠。
- **安全边界复核**:实例的 `otherProperty` **只含纯文本键**(Datasheet/Description/Value/Tolerance/Voltage Rating/Temperature Coefficient/LCSC Part Name/Supplier Footprint/JLCPCB Part Class),**不含引用键**,所以单改 Value 安全。但脚本仍须**程序性检查**有无 `Footprint/Symbol/3D Model/Device` 再写 —— 这是十几件全丢那次事故的红线,不能靠"我记得没有"。

**B. `autoconnect --spec` 批次过大会静默失败(最坑的一条)**

- 实证:上百条连接一次调用 → 返回 **`ok:false` 但列出全部条目且"0 失败"**,实际**一条都没落地**(网表 0 网络)。
- 单条同样的连接立刻成功 → 说明不是数据问题,是**长调用被心跳杀**。
- **正解**:**≤22 条/批 + 逐批校验 `ok` + 失败重试 + 末端网表回读比对**。实测重试能成(5 批里 2 批首次失败、重试通过)。
- ⚠️ **`ok` 字段才是真信号**,不要看"failed 数量为 0"。

**C. `--replace` 不可靠,改网用两步**

`autoconnect --replace` 多次报 `conflict` 且不生效。可靠模式:
```
sch disconnect --pin <D:P>   →   sch autoconnect --pin <D:P> --net <新网>
```
每步之间读回网表确认,不要连发。

**D. 坐标重叠 = 静默短路(新增门禁项)**

放件若与已有器件**同坐标**,引脚重合会被 EDA **自动连成同一网**,不报错。
实证:一颗电阻(`R1`)放在一颗电容(`C1`)的同坐标上 → 被并进 `C1` 所在的电源网 `NET_A`,直到 autoconnect 报
`pin already connected to net "NET_A"` 才暴露。
**批量放件前必须做坐标碰撞检查;终审加一项「同页同坐标器件数=0」。**

**E. `sheet-geometry` 的明细表 keepout 不可信**

- 该工具假设「右下角 = 高 x 高 y」,但实测本 build **y 轴向上、原点左下**,明细表在**低 y**。
  它报的 keepout 落在**右上角空白处**,照着避让等于没避。
- 非标图纸(如 500×300mm)还会报 `template "unknown"` + `fallback-ratio`,精度更差。
- **正解**:用一颗器件实放 + 截图实测确定 y 轴方向和明细表范围,然后**按构造避开**
  (例如全页限制 `x<=1450`),不依赖工具输出。A4 横版实测禁区仍是 `y<200 且 x>350`。

**F. 其它命令级坑**

- `sch delete --ids` 要 **JSON 数组**(`'["id"]'`),传裸 ID 报 `invalid --ids json`。
- `sch netlist` 导出的是**整份原理图文档(所有页)**,不是当前单页 —— 正好可一次验完跨页连通性。
- `sch page-new` 返回结构不稳定(有时 result 里没有 uuid);可靠做法是建完后从 `daemon health`
  读当前激活页(page-new 会把新页设为激活)。
- `sch rename`(原理图**文档**改名)会**静默失败**,需重试后用 `board list` 回读确认;
  `page-rename`(**页面**改名)有 `verified` 字段,可信。
- `sch check` 的 `multiNetWires` **把同名重复网标也计入**。硬门禁判据必须是
  `len(set(finding.nets)) > 1`(异名),同名(如 `GND、GND`)只是外观 lint。
- `lib search` 按 MPN 匹配,**中文关键词搜不动**;精确值要按厂商编码规则查
  (如 UNI-ROYAL `0603WAF` + 4 位码:187Ω=`1870`、5.23k=`5231`、29.4k=`2942`)。

**G. 换件时 `sch delete` 的返回值必须检查(否则悄悄多出一个重复件)**

换型标准动作是 `disconnect → delete → place → modify`。**`delete` 会失败**,
而如果不检查返回值直接往下走,后果是:

> 实证:换升压电感 `L1` 时 delete 静默失败,旧件仍在;新件因位号被占用被**自动编号成下一个空号(如 `L2`)**,
> 且与旧件**坐标完全重合**。更隐蔽的是——之后 `autoconnect --pin L1:x` 连的全是**旧件**,
> 新件一根线都没接。网表检查、单脚网、DRC 全都不报错(旧件接得好好的)。

**正解**:delete 后**循环读回确认目标位号已消失**(最多 3 次重试),确认后再 place;
终审加一项「**同页位号集合 == 期望集合**」,能同时抓到多件和漏件。

**H. `autoconnect` 单条也可能"假失败"**

实测出现过:脚本判定 `R1:2 → +3V3` 失败,但直接单发同一条命令返回
`state: "already-connected", currentNet: "+3V3"` —— 其实早就连上了,是**网表回读拿到了陈旧数据**。
**结论**:autoconnect 的失败判定不能只看一次回读;`already-connected` 是成功态,
终审一律以**重新导出的网表**为准,不以过程中的回读为准。

**I. 跨项目复制进来的器件 = 一个"全单脚网"的死端子**

用户从另一个工程把标准 TTL 下载端子整个复制到新图上,画面上看**完全正常**:
器件、封装、丝印、七根引脚外面都挂着漂亮的网标 `3V3 / 5V / MCU_BOOT / MCU_EN / UART_RX / UART_TX`。
但这些网标在**新工程里一个对应的成员都没有** —— 六条全是单脚网,整个端子除了 GND 一根线没连上。
更糟的是新板上本来已经有一个功能相同的下载口,于是变成**功能重复 + 半个死端子**。

- **DRC / `sch check` / 浮空引脚全绿**——因为每根引脚确实"连着一根线和一个网标",只是网标那头空无一人。
- 这是 §4.1「一致性≠连通性」的又一个实例,**只有离线跑网表数单脚网才抓得住**。
- **规矩**:任何"从别处复制/粘贴进来的器件",落图后立刻跑一次单脚网审计,并逐脚核对网名
  是否与本工程的网名体系一致(`3V3` vs `+3V3`、`UART_TX` vs `UART_TXD` 这种差一两个字符就是两张网)。

**J. 端子换型的安全流程(`sch place` 不能原地换器件)**

没有"改器件型号"的 API,必须 **断线 → 删件 → 同坐标放新件 → 改回位号 → 重新接线 → 网表逐脚核对**。
四个必须:
1. 换型前**先 `sch disconnect` 每一根已连引脚**,否则删件后会留下一堆孤儿网标/线段;
2. 删件后**断言器件真的没了**(§3.5 G 的静默失败);
3. 新件是自动编号(实测落成 `U?`),改回原位号时 **patch 必须带 `supplierId`**(§3.5 A),之后再补 `Value`;
4. 收尾**必须逐脚比对期望网名**,不能只看 autoconnect 返回 ok。
> 新工具下的现成脚本:本仓库 `tools/v2_swap_part.py`(原地换件,改前后网表护栏;工具手册 §2.14)。

**K. 控制台是 GBK,脚本里别打 ✓**

Windows PowerShell/Git Bash 下 Python 默认用 GBK 输出,`print("✓")` 直接 `UnicodeEncodeError` 崩在半路
——**而且往往是崩在"已经删了旧件、还没放新件"的中间态**。
自动化脚本一律只用 ASCII 记号(`[ok]` / `[PASS]` / `ABORT:`),或显式 `PYTHONIOENCODING=utf-8`。

---

**K2. 跨页/跨板脚本按位号定位,必须先锁板锁页**

一个工程里有多块板时,**位号会重名**。实测:板 A 和板 B 各有一个 `C1`,
我写了个 `{"C1": "47uF/10V"}` 的覆盖表去修板 B 那颗,脚本逐页跑,**把板 A 的 C1(10µF/10V) 也改了**。
`debug exec` 里的 `getAll()` 拿的是**当前页**的器件,循环切页时同一个 target 表会在每页各命中一次。

- **规矩**:任何按位号索引的 target 表,键必须带板/页前缀(`A/C1`、`B/C1`),或每页用独立的表。
- **兜底校验(推荐常设)**:**同一块板内,同一个立创编号的 Value 必须唯一**。
  这条一跑就能抓到上面这种误伤——同料号出现两个不同 Value 必然是写错了。
- 同理适用于坐标、primitiveId 之外的一切"人类可读标识"。

**L. 「先拆后装」的操作,装的前置校验必须在拆之前全部跑完**

实测事故:在同一条命令里先跑 `sch disconnect`、后跑 `build_page.py` 放件,
结果**放件被网格对齐断言拦下(坐标不是 10 的倍数),而断线已经生效** ——
三个 MCU 引脚一度悬空,状态比动手之前更糟。

- **规矩**:任何"拆掉再装上"的流程,**新件的库解析、坐标合法性、位号可用性必须先全部校验通过**,
  才允许执行第一条 `disconnect`/`delete`。
- 或者把拆和装放进**同一个带回滚的脚本**里 —— CLI 没有 undo,所以"回滚"意味着脚本自己要能把拆掉的接回去。
- 判据:**中途任何一步失败,系统必须停在"改动前"或"改动后",绝不能停在中间态。**

**M. 报警之前,先去查用户已验证板子的网表/参考设计**

实测:我算出"3.3V 经 10Ω 给屏背光,LED 的 Vf 差 0.4V 电流就差 5 倍,限流不可控",
准备报成必改项。翻出用户上一块**已实物验证**板子的导出网表后发现:
`+3V3 → R1(10Ω) → 背光 LED 阳极`、`阴极 → NMOS → GND` —— **与新板逐点一致,人家跑了很久没问题**。

- **凡是"沿用用户既有设计"的模块,先找那块板的网表/原理图**,逐点比对再下结论。
- 用户的 `.tel` / `.enet` 导出文件是**最高等级的证据**,优先于任何数据手册推演 ——
  它证明的是"这么接确实能工作"。
- 这次顺带用同一份参考网表交叉验证了 FPC 脚位、SPI 映射、RC 消抖网络、电平转换链,一次性关掉四个疑点。
- 反过来也成立:**参考设计里没有的东西,才是真正要盯的**(有一次漏掉的 I2C 上拉就是这么找出来的 ——
  参考板有 `4.7k×2`,新板漏了)。

**N. 开漏网络必须单独扫一遍(DRC 查不出)**

`I2C_SDA` / `I2C_SCL` / 各种 `INT` / `FAULT` / `DIAG` 都是开漏,**没有上拉在网表上完全"正常"**:
两个成员、不是单脚网、不是死链、DRC 全绿 —— 但物理上永远拉不高。

**终审加一条**:把所有开漏/漏极开路信号列出来,逐条确认**有外部上拉**。
"MCU 内部弱上拉够用"不能作为设计依据 —— 复位期间内部上拉未配置,且阻值(几十 kΩ)对总线电容余量太小。

## 4. 电路检查 SOP

### 4.1 一致性 ≠ 连通性 ⚠️(最容易漏的一类)

sch↔pcb 零失配、浮空=0、DRC 通过——**这三样全绿也挡不住"单脚网"**(两边一致地断着,连飞线都不生成)。
> 血案:一颗 LED 另一端悬空,连过三轮审查没人发现。

**任何终审必须加"连通性语义审计"**(拿网表文件**离线**跑,不依赖画布):
1. **单脚网清单** — 成员数==1 的网全部列出,预留脚需白名单化
2. **死链检查** — 被动件链(R/C/L/D/FB…)两端必须都到"锚点"(电源网 / IC / 连接器);只连到彼此的孤岛=死链
3. **芯片供电名引脚**必须挂在电源网上

### 4.2 门禁清单(全 0 才算过)

`sch check`(旧 CLI)八项:`multiNetWires`(异名多网线)、`geomNetMismatches`、`netMarkerMismatches`、`danglingWires`、`zeroLengthWires`、`floatingPins`、`wireCrossings`、`wireOverPins`。
- **异名 multi-net = 0 是硬门禁**;同名重复网标 = 外观 lint,单独分类不进硬门禁。
- 官方 DRC 分级:门禁看 `fatal=0 && error=0`;warning 逐条归类(合法 NC / 工具限制 / 真实项)。**禁止为了消警把 NC 脚接地**。

#### 4.2.1 🔴 第三类门禁:**几何连通性**(2026-09-10 新增,血案背书)

§4.1 讲的是"网表自洽但电路不成立"。**还有一类反过来:网表说连上了,几何上根本没碰到。**

> 血案(某板):电池座被脚本自动转了 90°,引脚移位,导线还画在旧坐标上。
> 但因为**导线被赋了同名网络名**,网表照样把它列进电池负极那张网,检查全绿,DRC `fatal=0`。
> 直到把导线网名清掉,两个引脚才掉进自动网(`$1N…`)暴露出来。
> 同一轮还查出 2 个网络符号被**吸附到 5 网格**后与线端错开 1 单位——同样被网名掩盖。

**因此,凡是脚本画的图,终审必须加三项纯几何检查(全 0 才算过):**

| # | 检查 | 判据 |
|---|---|---|
| 1 | **引脚侧** | 每个非 NC 引脚的坐标上,必须存在某根导线的端点 |
| 2 | **符号侧** | 每个 netFlag / netPort 的坐标上,必须存在某根导线的端点 |
| 3 | **网名侧** | **导线一律不许带网络名** —— 带了不但图面文字翻倍,还会掩盖第 1、2 项 |

参考实现:本仓库 `tools/v2_geom_audit.py`(一条命令扫全部页;项目根放 `project.json`,见工具手册 §2.14)。

#### 4.2.3 🔴 改文档也要"全文扫描",不能只验被改的那一句

> 血案(某板,2026-09-10,**连续三轮审查**):每一轮的文档 [必须改] 都是同一种漏法——
> **被点名的那一句改对了,紧挨着的同源句原封不动。**
> 例:两处都改成"≤80MHz 时两种路由表现相同"了,**紧挨着的下一行**还留着"我们的映射优于厂家参考";
> 刚订正完某个脚的接法,**下一行**还写着"电源使能未定义"(而该脚是硬接 +3V3 的)。

**根因**:验收脚本查的是"**我替换的片段是否生效**",而不是"**这个错误论证在全文还有没有第二个实例**"。
这和工具手册坑 ⑪(日志打的是意图,不是 API 的返回)是同一族,但更隐蔽——**这次连结果都验了,只是验错了对象**。

**正解(改任何文档都适用):**
1. 写盘**之后**逐条回读,确认新文本真的在文件里(防脚本中途异常导致前几处没落盘);
2. 再按**语义关键词**扫全文(不是扫被替换的片段),把该错误论证的**所有实例**列出来;
3. **人工区分"引用旧错误的订正句"与"仍在生效的错误论证"** —— 前者必须允许保留,
   否则你会把自己的纠错语句也一起删掉。

> 💡 这条对**代码**同样成立:改了一处 bug 之后,用"这个错误模式"而不是"这段被改的代码"去 grep 全库。


#### 4.2.2 🔴 三道机械化门禁同时失效的那一类:**多脚器件的内部拓扑**

> 血案(某板,2026-09-10):一颗侧按开关有 4 脚,引脚名是 `A/B/C/D`。
> AI 只按引脚坐标把它们分成"左两个/右两个",当作两个触点节点接线。
> 实际 `1/2` 是触点、`3/4` 是**金属外壳**——实物上外壳是一整块,于是按键被**永久短路到地**。
>
> **网表检查、几何审计、DRC 三道门禁全部通过** ——
> 因为 EDA 不知道"外壳两脚在实物上是同一块金属",它们在网表里就是两个独立引脚。
> **是用户看图发现的。**

**判据(承接 §4.3 极性核对与工具手册 §2.10):**

| 引脚名读出来是 | 能不能直接接 |
|---|---|
| 功能名(`G/S/D`、`A/K`、`VDD/SCL/SDA`) | 可以 |
| **纯数字**(`1/2/3`) | ❌ 必须拿实物/数据手册/已验证板网表 |
| **字母但不是功能名**(`A/B/C/D`) | ❌ **同上** —— 它看起来像功能名,其实什么也没说 |

**多脚器件(≥3 脚)接线前必须回答一个问题:哪几个脚在器件内部是同一个节点?**
引脚坐标只告诉你脚在哪,**不告诉你拓扑**。答案只能来自:符号的画法(线怎么连、有没有接地标记)、
数据手册、或实物万用表。**并且这类结论必须进首板必测清单**,因为软件端永远验不出来。

> **推广到一切"AI 画图"场景的通则**:
> **凡是"名字相同就算连上"的机制(网络名、网标、同名端口),都会掩盖几何断路。**
> 所以自动化产出的图,**几何检查必须独立于名字**——只比坐标,不比名字。

#### 4.2.4 器件标准化告警的收敛与验证(2026-09-14 实测)

“器件标准化”是**实例属性/库对象一致性检查**,不是电路功能验收。标准化清零不能替代连接语义、几何、电气额定、PCB DRC 或样机验证；反过来,也不能为消警而一键换件,把符号、封装、Unique ID 或 NC 一并改掉。

按下列顺序执行并保存证据:

1. **冻结双基线。** 导出修改前原始源、对象/引脚、规范化 Protel2 网表和原生 DRC。网表基线分成两层:器件属性允许差异白名单；网络及逐脚成员必须单独零差异。几何也分成“本体/属性位置样式”和“导线端点、netFlag/netPort、NC”两组核验,不能用网表相同代替接线/NC未变。
2. **逐告警确认标准来源。** 把位号、商城号、MPN、`Value`、额定值、制造商、符号和封装列成矩阵,对照当前商城条目及原厂资料。旧商城号失效时先确认现行条目确为同一型号,再核对引脚表与真实封装几何；收购后的品牌归属变化不能单独作为拒绝或替换依据。
3. **R/C 字段与显示分离。** 物料 `Value` 使用商城标准写法；电压等额定放独立字段；图面旧标签放隶属元件的 `Display Value`。`Display Value` 是字面量,后续改物料值时必须同步。`Name` 的公式、显示状态和展开结果也要回读,因为标准化比较展开后的 `Name`,只改 `Value` 不够。具体 API 坑见工具手册 #56。
4. **需要换库对象时走原生器件管理器。** 先只选唯一目标,明确是否保留位号、Unique ID、当前符号、当前封装和属性来源；封装确需更新时不要勾保留当前封装。实测可用的路径是“使用推荐器件 → 器件管理器”；PCB 侧若由用户亲自更新,Agent 只能按真实操作主体记录,不得改写成自动同步成功。
5. **原理图独立复验。** 另起调用确认原生 DRC 结果；同时核对 UI 中全部检查组与预期一致,不能以“未检查/关闭检查”冒充0。再做属性白名单 diff、规范化网表逐脚零差异、几何三查、NC 和元件身份/Unique ID 对账。即使原理图 DRC 为空、UI 各检查组都与预期一致,也只证明本次标准化及连接/几何门禁通过。
6. **PCB 影响单列。** 对换封装对象逐焊盘比较编号、网络、位置和几何；全板比较元件数量、位号、Unique ID、位置、方向、层、非目标器件几何以及原生 PCB DRC 分类计数。几何比较要容许有证据的序列等价与数值舍入,但必须量化最大差值；闭合多边形可按边集合核验,不能只比顶点遍历方向。换库后再看位号丝印的字号、线宽、锚点和可读位置,因为器件位置保留时这些样式仍可能恢复库默认。合格结论的写法类似:「全部器件身份/放置保留、全部焊盘网络不变、非目标器件几何不变;未连接项前后数量相同、无新增」——它不代表这些未连接项已解决,也不代表可制造。
7. **持久化结论最后写。** 如果项目要求保存重开,只能在重开后重新拉取源、对象、引脚、网表、原理图/PCB DRC并重复上述门禁后宣布完成。保存重开仍在进行时,文档必须写“待验证”。API 删除旧文本后重现而原生删除稳定的案例只证明两条路径结果不同,原因未证实时不猜因果。重开后的证据至少包括:原理图的器件/引脚/网络数、显示标签/文本数、DRC 结果和规范化网表 SHA-256;PCB 的器件身份与放置、全部焊盘网络、非目标器件几何,以及未连接项的前后对比;工程导出包。换库对象再逐项比焊盘中心、`defaultPad` 形状/尺寸、`padAngle`;`padOffset` 只接受亚 mil 级的舍入差并写出最大差值;反向顶点序列的 FILL 按闭合边集合判等。这些全过也只说明当次标准化保存重开与几何等价门禁通过,不表示源文件逐字段完全一致,也不能写成整板 DRC 或制造放行。

以上流程来自一次真实工程的标准化告警收敛(实测记录未公开);跨项目只复用流程与判据,不复用其中的数量、位号和坐标。

### 4.3 极性核对(必做,别靠猜)

二极管/TVS/LED/电解电容:**引脚名优先**(A/K、+/−);引脚名是纯数字时,**放大快照目视确认**再接线,并把结论写进文档。
> 常见坑:系统库符号图形画反(引脚绑定正确、实物无害,但审图会误判)。最干净的解法 = **换同型号其他厂商的库件**。

🚨 **扩展到"引脚名是纯数字"的所有连接器 —— 不只是极性件**(2026-07-28 实证)

FPC 排线座、电池座这类器件,符号引脚名往往就是 `1,2,3,4…`,**没有任何功能信息**。
凭"常见 pinout"推断会错,而且错得很危险:

> 实证:某块小尺寸 SPI 屏的 FPC 排线座,我按"常见排列"推断了背光、电源、地几个脚,
> 实际定义**整体错位一位**。后果:
> ① 把 **+3V3 接到了屏的 GND 脚** = 电源对地直接短路;
> ② 把 **背光阴极接到 GND** = 背光绕过限流电阻和 MOS,上电即烧背光。
> 这两条 `sch check`、DRC、单脚网、死链检查**全都发现不了**(两边"一致地错着")。

**铁律:纯数字引脚的连接器,必须拿到下列之一才能接线**
1. **同一块屏/座子在已验证板子上的网表文件**(最可靠,直接照抄);
2. 厂商数据手册的 pinout 图;
3. 用户口述 + 实物核对。

拿不到就**留 NC 并显式列入必核清单**,绝不"按常理"填 —— 留空最坏是功能缺失(可恢复),
猜错可能是短路(烧板)。有一次某个 FPC 脚当时读不到定义,先留 NC,后来拿到用户已验证板的网表才补上。

> 🔴 **2026-07-30 再次实证(某板,AI 犯的)**:一个 3 脚输出端子,符号上只有 `1/2/3` 没有功能名。
> AI **按"引脚顺序"猜了正极、负极和空脚** —— 和实物定义对不上,**三个脚全错**。
> 后果:**负载反接,所有输出全部不工作**。DRC / 网表 / 单脚网 / 两端同网 **一条都抓不到**
> (拓扑完全"正确",只是接到了错的物理脚)。
>
> **教训**:「按顺序猜」是最容易自我说服的一种猜法,因为它看起来有规律。
> **本条铁律没有例外**:拿不到实物/手册/已验证网表,就 **留 NC + 进必核清单**,
> 不要因为"只有两根线、猜错顶多不工作"就放低标准 —— 所有输出一起不工作时,
> 现场第一反应会去查电源和固件,而不是查一个"看起来接好了"的端子。

### 4.3.1 连接器选型核对(两条,DRC 一条都查不出)

**① 额定电流 vs 实际电流 —— 必须实算,不能"看着像够"**

`sch check` / DRC / 网表审计**全都不看端子额定**。器件参数里的 `额定电流` 字段必须逐个连接器人工比对。

> 实证:某板一路输出用 SH1.0-3P 端子(额定 **1A**),按供电电压和负载的线间电阻实算,
> 电流 **峰值是额定的 2 倍** —— **连 RMS 都超额定约四成**。

常用系列速查:**SH1.0 = 1A ｜ PH2.0 = 2A ｜ XH2.54 = 3A**。
驱动三相电机时,算相电流别用母线电流代:三相 SVPWM 满调制下 `I_line_RMS ≈ 0.707×V_bus / R_线间`。

⚠️ **算出超额定 ≠ 一定换件 —— 先问"这个端子我能不能选"**

上面这个例子我第一反应是换成 PH2.0-3P(2A),**结果是错的**:
**对端线束自带的插头就是 SH1.0-3P**,板端只能配它,没有选择余地。
这类"对端线束已经定死"的场合很常见:成品屏的 FPC、成品电池的插头、成品风扇/水泵、别人家的模块。

**正确顺序(不能颠倒)**:
1. **先算账** —— 超额定几倍、对应温升多少、是**连续**还是**脉冲**,写清楚;
2. **再问对端能不能改** —— 能改就换件;**不能改就转成「限流 + 热设计 + 留后路」**:
   固件限连续电流(滑动窗平均即可,不必上严格 I²t)、缩短线长、
   **PCB 上给该端子旁边预留直焊焊盘**,将来真不够就剪掉端子直焊;
3. **无论走哪条路,这笔账都必须落进文档**。硬件"没改"不等于"没问题"——
   固件那边不会自己知道存在这么一条连续电流上限,不写下来就等于没有。

📌 更一般的教训:**"这是个 bug"和"这个约束是外部给定的"要分清**。
先弄清楚哪些量自己能选、哪些被上下游定死,再决定改哪里。
把外部约束当成自己的选型失误去"修",白改一轮还会引入新风险(端子一换,原配线束就插不上了)。

**② 同规格端子并排 = 误插风险**

同间距、同脚数、相邻摆放的两个端子,插错是**装配时的必然事件**,不是概率事件。
DRC 不管,网表也不管,只有人能看出来。

**规矩(推荐做成公司级)**:

> **功率一种间距、信号另一种间距。** 例:PH2.0 只走电源/功率,SH1.0 只走信号。
> 间距不同 = 机械上根本插不进去,是**唯一不依赖装配纪律的防呆**。

> 实证:某板上一个电源输出端子和两个信号输入端子都是 PH2.0-2P 并排,
> 把电源插头插进信号口就是直接拿 5V 打 MCU 的 GPIO。两个信号口改走 SH1.0-2P 后物理隔绝。

剩下的同规格对(如两个 SH1.0-2P)要**逐对论证插反后的后果**:
若两边都是"GPIO+上拉、按键对地"这种同构低压输入,插反只是功能错位、不损坏,可接受;
只要有一边带电或带输出驱动,就必须换脚数或换间距。

### 4.4 几何检查分层

bbox 间距通过后,还要独立查:①异网引脚同坐标 ②短引线端点重合 ③引线段相交。`layout-lint` 只看包围盒。

### 4.5 规格书逐条复核(DRC 和网表都查不出,2026-10-07 审查实证)

网表和 DRC 只管「接没接、接对网没有」,下面几类只能对着规格书一条条核:

| 查什么 | 怎么查 | 实证 |
|---|---|---|
| **NC / Reserved 脚** | 每个打 NC 叉的脚回规格书 pin 表看原话(§3.2) | TPS55340 的 11 脚符号上叫 NC,TI 规格书要求接地 |
| **保护器件的动作点 vs 后级绝对最大值** | TVS 的 VBR(min)、保险丝的动作电流,要低于被保护器件的**绝对最大值**,不能只看「高于正常工作电压」 | 例:VIN 绝对最大 34V 的芯片,用 VBR 从 33.3V 起的 SMAJ30CA 就不够(33.3V 只是 VBR 的下限,上限和钳位电压都高于 34V);降一档(如 SMAJ26CA)的前提是输入电源的最高设定不超过它的 VWM |
| **器件温度等级 vs 装机环境** | 模组、晶振、电解电容的工作温度,对照装机环境温度和板上热保护门槛 | ESP32-S3-WROOM-1 的 R8 / R16V 系列只到 65°C(§11.1);板上散热或热保护的动作门槛比这还高时,模组会先超出额定 |
| **ESD 阵列的 VBUS 脚接在哪** | 和 VBUS 检测分压共节点时会被 MCU 的 D+ 上拉倒灌 | §11.5 |
| **文档里的数字回到一手资料** | 耐压、阈值、引脚定义逐个对规格书;别引用自己以前写过的数 | 项目文档里抄的输入电压范围和「绝对最大值」都是错的——把开关脚(SW)的额定当成了 VIN 的 |

## 5. BOM 整理 SOP

### 5.1 数据来源

- **原理图是 BOM 的单一真源**(带 `addIntoBom` / DNP 语义)。
- 逐件取:`designator`、`supplierId`(立创编号)、`manufacturerId`(厂牌型号)、`manufacturer`、`otherProperty.Value`、封装名、`addIntoBom`。
- **导出前先跑 §3.1 的参数包同步**,否则 Value 空白、供应商号是错的。

### 5.2 必备字段与写法

| 列 | 要求 |
|---|---|
| 类别 | 电阻/电容/连接器/IC/二极管… |
| **LCSC 编号** | **必填**,采购唯一依据 |
| 厂牌型号 | Manufacturer Part |
| 制造商 | — |
| **规格 / Value** | **参数要写全**:电容必带**电压**(如 `100µF 35V ±20%`)、电阻带精度功率(`10kΩ ±1% 1/8W`)、二极管带关键电压 |
| 封装 | 完整封装名(用于核对脚位) |
| 数量 / 位号 | 同料号**合并成一行**,位号列全 |
| 备注 | **DNP/不贴**、自备料、替代料 |

> 🔴 **LCSC 编号必须是商城料号**(2026-10-07):EDA 库里有一类 `C99…` 开头的条目(厂家、JLCPCB Part Class、规格书全空),
> `getByLcscIds` 查得到,但**不是商城编码,下不了单**。实测某板上一颗模组、一颗连接器的编号都是这种(`C99` 后面跟一串数字),
> 两份采购 BOM 对它们的型号写法还互相矛盾。出 BOM 前把 `Supplier Part` 以 `C99` 开头、或 `JLCPCB Part Class` 为空的件全挑出来核;
> 换成商城件时,新库件的符号可能和旧的不一样(工具手册坑档案 #81)。
> 另:库条目的 Value 可能是怪值(模组 `C2913202` 的 Value 是 `2.4GHz`),会原样进 BOM 的 Value 列——按编号下单不受影响,人看 BOM 时别被误导。

### 5.3 口径

- **DNP 件**(`addIntoBom=false`):留焊盘不贴 → BOM 里**列出但标"不贴/0采购"**,别直接删(否则将来没人知道那个焊盘干嘛的)。
- 多套采购:整板乘套数,**被动件另加余量**(常用 10%)。
- 替代料:**结论必须落文档**并注明"已采用/未采用",避免以后翻记录误改。

## 6. 高效执行模式

> 本章的命令名和实测数是旧 CLI 时代的,原则不变;新工具下的同一套做法(一次 `/execute` 塞一整段状态机、每批塞多少)见工具手册 §4.2。

- **一轮外层调用驱动整段状态机脚本**:AI 只在脚本前后思考,步间不回模型;几十条 CLI 调用在脚本内连续跑完。
- **验证三级制**:①事务前存一次基线(位号/primitiveId/采购号/坐标/pin-net);②**步内只查本步改动**(删后查旧ID消失、放后查"目标库件恰好1件"、改后只核关键字段、接后只核该件 pin-net)——禁止步步全页 check;③末端一次总账(save→reload→新网表→全板 diff→check/DRC)。
- **首件 canary**:批量前先跑一件全流程,通过再放量。
- **批量 spec**:`sch autoconnect --spec <json>` 一条命令接多网,逐脚调用是浪费。
- **短轮询 settle**:100–700ms 递增轮询,取代固定长 sleep。
- **幂等**:脚本先查现状再决定动作,可安全重跑。
- **fail-fast**:第一处断言即停,打印 expected/actual + 位号 + 阶段;基线/审计/终报三份产物留档。

### 6.1 量化基准(拿来对标自己慢在哪)

| 操作 | 实测 |
|---|---|
| 两脚件完整换装(原理图+PCB+保存+验证) | **21.7 s / 件**(热状态 15~25 s) |
| 仅 PCB 批量换装 | 48 件 / 312.5 s ≈ **6.5 s / 件** |
| 单件真正改设计的写调用 | 6~8 次 |
| 大件换型(19 网 + 双面 + 整板差分 + DRC) | 14 分 37 秒(不是普通基准) |

**如果你现在是 30~90 s/件,差距多半不在 API 数量**,而在三件事:
每次调用之间是否回到模型、是否用了固定长 sleep、是否重复做全板检查。

> 实测参考:一次防御型 `apply-one` 内部展开约 **80~110 次** CLI→daemon 往返,
> 但**外层 AI 调用只有 1 次**。这就是"一轮外层调用驱动整段状态机脚本"的实际含义。

## 7. 原理图排版五规(用户实践)

1. **横向间距放大、竖向可紧凑** — 网标从引脚两头**横向**伸出,横排太近会两头叠标。
2. **网标尽量横排** — 竖排网标易与邻标重叠,重叠可致同点异网/意外短路。
3. **避开图框右下明细表禁区**(实测范围远大于工具报告值;新工具下的实测办法与数据见
   《EDA工具手册-easyeda-api官方桥接-跨项目版.md》§1.5)。
4. **图纸开大一点,别省纸**(2026-07-29 补充)——默认 **500 × 300 mm**,不用 A4。
   > 理由是实打实的:AI 放件间距不够时,**网标会叠到一起,导致同点异网/意外短路**(§3.5-D)。
   > 图纸放大是消除这类问题最便宜的手段,没有任何代价。设法见工具手册 §1.5。
5. **器件摆放:左芯片 / 右阻容 / 分类成行**(2026-07-29 补充)
   - 每个功能块:**芯片放左边**,它的**电阻电容电感放右边**,同类归拢,**一行一行排**;
   - 🔴 **右侧阻容必须按"服务于哪颗芯片/哪个功能"分组,每组上方加一行文字标注**,例如:
     ```
     U1 降压芯片外围           U2 MCU 去耦
     C1  100nF  输入去耦        C11 100nF  VDD3P3
     C2  22uF   输入            C12 100nF  VDD3P3_RTC
     R1  240k   EN 上分压       ...
     ```
   - **为什么必须加标注**:阻容一旦堆成一片,就丢失了"这颗 100nF 是给哪个引脚去耦的"
     这个信息,而 §8.4-6 明确要求 PCB 阶段"**去耦贴引脚,不贴组**"——标注是这个信息
     从原理图传到 PCB 的唯一载体。没有它,分组表就要靠人重新推断。

### 7.1 页面怎么分(2026-07-29 补充)

**一页一个功能块,宁可多分几页。** 判据不是"放不放得下",是"**这一页能不能被独立看懂和独立审查**"。

三条具体原则:

1. **电源单独一页** —— 所有电源域(输入保护 / 各级变换 / 采样)集中,别散到各功能页里。
2. **同构的重复电路拆成结构完全相同的多页** —— 比如多路驱动拆成两页,每页路数相同。
   > 这不是为了放得下,是为了**逐行对照**:两页长得一模一样时,"某一路漏接一根线"
   > 这类错误(§3.5 的高发项)一眼就能看出来;混在一页里反而难发现。
3. **接口/连接器按物理位置归页**,不按信号类型 —— 装配和排查时人是按"哪个口"找的。

页面划分与命名定下来后**写进项目文档**(§0 检查单已要求),不要只记在脑子里。

### 7.2 芯片与外围分区版式（2026-09-14 起的默认标准）

默认按这套版式整理：**按“芯片服务关系”分组，不按电容/电阻品类堆成全页长列。** 用户明确满意后冻结版式，完成必要验证即交回，不继续无谓美化。

1. **一块电路一个清楚的区。** 主控、功率驱动、反馈采样、传感器、通信/隔离、复位各有标题；按实际复杂度合并或拆分，不机械套相同数量的框。主芯片为视觉中心，外围位于同区右侧或下方；跨区接口紧邻其服务电路。保留原有图纸能装下就合理利用；确实拥挤再扩大，不靠缩小字体硬塞。
2. **芯片外围再按引脚功能归类。** 数字电源、模拟参考、驱动VM、内部稳压、电荷泵、配置、使能/故障分别形成小组。注释指出服务对象/引脚，如“VDDA/VREF+去耦”“AVDD储能”，避免只写“100nF电容”。原理图同组不等于PCB可随便靠芯片；PCB仍按真实引脚回流/环路放置。
3. **重复电路同构对齐。** 多相采样、多通道保护使用相同顺序、方向、间距；每路的串阻、对地电容及网络名一眼能对应。关联RC成对摆，不把电阻放一个区、电容放另一个区。优先短直连接或清晰的同名端口，不画跨越多个分区的长线。
4. **三级文字，统一样式。** 功能区标题最大且适度加粗，位号/数值保持一致，功能说明较小但在常用缩放下可读。轻量无填充边框、统一边距及区间留白；说明不压线、不碰端口名、不挤进右下标题栏。长装配说明单独留位置，不能为了整洁删掉“不装端子/直焊/应力固定”等要求。
5. **迁移注释同步更新。** 芯片型号、外围功能、配置档位、信号名称按最新设计核对；旧驱动、旧参考电压或旧采样方法的文字不能残留。物料显示数值须与准确料号一致，发现字段冲突先查当前料库/原厂资料，再只改已确认错误字段；不为消警一键标准化。
6. **排版与电气验收分开。** 移动本体时连同所属短线、端口、电源符号、NC及注释完整处理；身份、位号、料号、封装、Unique ID、PCB绑定与引脚网络保持。纯排版核网表零语义变化、几何三查及原生DRC；必要的物料文字纠错另列白名单差异。用户再次手调后按最新状态重新取基线，禁止回放旧排版。

执行方法和工具限制见工具手册 §1.7.11。

**执行细则(2026-10-07,两轮独立审查后定稿)**:
- 加件、补线之前,先量本页现有的短桩长度和端口列位置,照抄;别套脚本默认值(实测:某页短桩是 10,脚本按默认 20 补了几行,端口列就错开了)。
- 芯片的功能说明优先放在右侧标签列之后;右边紧挨区框放不下时,放在芯片上方、位号右边,离外框 ≥ 4 单位(贴在外框线上也算压线)。
- 重复电路逐项同构:器件、端口、短线长度、注释相对主芯片的偏移都一致;区框以主芯片为锚,取各路的并集,统一成同一个相对框。
- 注释与端口名、导线的间距用几何脚本查,再放大截图目视;两样都过才算。
- 用户在界面里手调过的版面(区的位置、对齐方式)要保留;重算区框时沿用用户的对齐方式,只按内容撑开。
- 注释内容也要逐条对网表和最新设计核(本节第 5 条):实测一轮就在近两百条注释里查出写反的接口线序、过时的电流设定值、早被推翻的旧结论、上下颠倒的选型表。

## 8. PCB 布局与分组 SOP

> 这一章解决的问题:**器件从原理图落到 PCB 后是一大坨,人根本分不清哪堆是哪堆**。
> AI 做"归类打包",人做"摆位和布线"——这个分工经实证最顺。
> 本章的 `pcb …` 命令名是旧 CLI 的,分组方法本身与工具无关;PCB 作业的完整方法和新工具下的写法见《PCB操作手册》。

### 8.1 分工模型(不要越界)

| 步骤 | 谁 | 做什么 |
|---|---|---|
| 1 | 用户 或 AI | 把器件弄上 PCB(见 §8.2) |
| 2 | **AI** | **按功能分组,打包成紧凑方块,组间拉开** —— 不摆最终位置 |
| 3 | **用户** | 把每个方块整体拖到结构上想要的位置 |
| 4 | AI(可选) | `pcb auto-place --multi-gap 0`:锚点原地不动,外围件贴到"它实际连接的引脚"最近的芯片边 |
| 5 | **用户** | 布线。**此后 AI 永不再移动任何器件**(§1-9 铁律) |

**为什么是"打包"而不是"直接摆好"**:最终位置由**结构**(外壳、按键帽、屏、接口开孔)决定,
AI 不掌握这些信息。AI 能提供的价值是**把功能关系可视化**,让人拖一次方块顶拖二十次散件。

### 8.2 器件怎么上板

- 🚨 `pcb import-changes` **永久拉黑**(§1-2)。
- 路线一(**推荐**):**让用户在 GUI 里自己做原理图→PCB 同步**。省事、无风险,AI 只管后续归类。
- 路线二:`pcb add-component` 逐件加(带 `--designator --unique-id --nets`,参数从 `sch read` 取)。
  适合"原理图后来又加了几个件"的增量补齐。
- **每次都要对账**:原理图件集 vs PCB 件集,查三样 —— **缺件 / 孤儿 / 料号不符**。
  ⚠️ 用 `delete+place` 换过型的器件会拿到**新的 uniqueId**,PCB 那边会变成孤儿或料号不符,必须补同步。

### 8.3 功能分组怎么分(纯算法不好使)

**先说什么不管用**:按"共享网络的亲和度"自动分组会得到垃圾结果 ——
MCU 和电源网会把几乎所有件都吸走(实证:一颗 MCU 吸走三十多件、充电 IC 吸走二十多件,还剩十几件无处安放)。

**管用的做法**:按**功能块**人工分组,每组认一到两个**锚点**(位置由结构决定的件):

| 典型组 | 锚点 |
|---|---|
| 输入接口与 ESD | 连接器本身 |
| 每一路开关电源(降压/升压/充电) | 那颗 IC |
| 电池与保护 | 电池座 + 保护 IC |
| 主控 | MCU/模组 |
| 下载/调试口 | 连接器 |
| 板间接口 | 连接器 |
| 显示 | 屏座 |
| 输入器件(编码器/按键) | 器件本身 |
| 指示(LED/蜂鸣器) | 发光/发声体 |

**分组表里每个件都要写清"为什么在这一组、要贴谁"** —— 这份表比坐标更有长期价值,
布线时人会反复回来查。

### 8.4 🔴 六类"不能只按贴芯片处理"的例外

这是分组表里最值钱的部分。纯按"贴它连的芯片"会把这几类放错:

1. **测温元件贴热源,不贴它的分压伙伴** —— NTC 是测电池/功率器件温度的,必须贴被测物;
   它的分压电阻才贴 IC。
2. **串阻贴"被保护的那一端"** —— 保护 MCU 引脚的串阻靠 MCU 放,不是靠连接器。
3. **一进一出的串阻要拆开放** —— 电平转换/缓冲器的输入串阻靠输入侧、输出串阻靠输出侧。
4. **RC 滤波要拆开** —— 电阻靠信号源(如分流电阻),电容靠采样端(如 MCU 的 ADC 脚)。
5. **上拉/下拉贴"定电平的那个脚"** —— 尤其 BOOT/复位这类,贴 MCU;放到连接器那头会被走线电感毁掉。
6. **去耦贴引脚,不贴组** —— 多路 VDD 的芯片,每个 100nF 有它自己的引脚归属,写进表里。

### 8.5 打包算法与两个包围盒的坑 ⚠️

货架式装箱(按高度降序、行宽逼近正方形)就够用。关键在**包围盒怎么算**:

**坑 1:焊盘范围会严重低估"本体比焊盘大"的件。**
电池座、蜂鸣器罐、无线模组、FPC 座、轻触开关都是这类。只按焊盘算会重叠。
> 实证:第一版打包出二十来处重叠,全在这五类件上。某无线模组焊盘范围 17.5×17.8mm,本体是 18×25.5mm。

**正解**:从**封装名里编码的尺寸**兜底 —— 多数库件名形如 `XXX_L<长>-W<宽>-P<间距>-LS<跨距>`,
解析出来和焊盘范围**两轴各取 max**。名字里没尺寸的(FPC 座、异形件)手工查表。

**坑 2:🔴 不能用 `rotation` 判长边朝向。**
封装的"L 轴"画在 x 还是 y **并不统一**。按 rotation 换轴会把件算错。
> 实证:一个电池座 rotation=90,按常规换轴后被算成 87×77mm 的大方块(实际 77×20.7mm)。

**正解**:**用焊盘包围盒的长短轴来对齐** —— 焊盘哪个轴长,封装的长边就归哪个轴。
这个判据不依赖任何封装绘制约定。

**参数经验值**:件四周留白 20mil、组内件间距 25~35mil、组间 450mil、每行 3~4 块。

### 8.6 复验门禁

| 项 | 判据 |
|---|---|
| `pcb layout-lint` | **重叠 = 0、越界 = 0、紧贴 = 0**(硬门禁) |
| 原理图↔PCB 对账 | 缺件 = 0、孤儿 = 0、料号不符 = 0 |
| ratsnest 总长 / 交叉数 | **只作改善指标,不作门禁** —— 分组阶段是为了可读性,不是为了可布线性 |

> `layout-lint` 的 0~100 分在分组阶段必然很低(方块阵列的飞线交叉一定多),**别去优化它**。
> 真正的布线友好度要等用户摆完位再看。

### 8.7 布局硬约束速查(放大器件时同时满足)

1. **无线模组天线净空** —— 天线端优先出板边;否则按原厂图在**所有铜层和器件层**留净空,
   成品结构内四周尽量 ≥15mm,远离电池、电机、磁铁、线束、金属件。
2. **带 EP 的功率器件** —— EP 焊到完整地平面 + 导热过孔,做温升试验。
3. **磁传感器 = 机械基准点** —— 磁编码器/霍尔的封装中心必须对准转轴(±0.25mm 级),
   **板框和安装孔要以它反推**,不能等器件摆完再补。坐标交给结构后不得再挪。
4. **大电流路径要粗要短** —— 电池链、功率级输出、电机相线,按峰值定线宽。
   ⚠️ 保护 MOS 的**走线电阻会叠加进过流检测**,直接影响跳闸点,务必最短。
5. **每个开关电源的环路面积压到最小** —— 电感 + 输入输出电容 + IC 的 PGND。
6. **FB 分压走线远离对应的 LX/SW 节点**。
7. **USB/高速差分对** —— 阻抗、等长、参考面连续、少过孔;ESD 器件在差分线**中途**不绕远。
8. **测试点预留** —— 各电源轨、关键控制信号、采样节点 + 足够的 GND。

### 9.1 怎么唤起对方 AI(以 Codex 为例)

#### 9.1.1 标准命令模板

**保证 UTF-8 输入**:消息先写进 UTF-8 文件再管道进去,别在命令行里内联中文。bash、PowerShell 都能用,写法见工具手册 §6.1。

```bash
cat 消息.txt | codex exec -m <模型> -s workspace-write -C "<工作目录>" --skip-git-repo-check \
  -c 'sandbox_workspace_write.network_access=true' --color never -
```

| 部分 | 为什么必须这样 |
|---|---|
| `cat 文件 \| ... -` | 消息写进 **UTF-8 文件**再管道进去。命令行内联中文会被编码坑掉 |
| `codex` | 入口和版本每次现查(`codex --version`);装法、版本要求见工具手册 §6.1 |
| `-m <模型>` | 显式指定模型,别依赖 config 里的默认值(默认值会被人改) |
| `-s workspace-write` | 审查者要自己写结论文件时才给。**对 EDA 的"只读"是靠提示词里的红线约束行为,不是靠沙箱**(它经网络调 Bridge,沙箱拦不住 EDA 写操作),两者别混 |
| `-C "<工作目录>"` | 目录锚点,也是对方能写的范围 |
| `--skip-git-repo-check` | 目录不是 git 仓库时必须加 |
| `network_access=true` | **放行本机 Bridge**(127.0.0.1:49620-49629)。不加这条对方连不上 EDA |
| `--color never` | 输出干净,便于程序解析 |

> ⚠️ **风险提示**:`workspace-write` 让对方能在 `-C` 目录下写文件,`network_access=true` 让它能联网。所以:
> ① `-C` 指到完成任务所需的**最小目录**,别指到整个工作区或家目录;
> ② 结论写到**单独的目录**(或项目文档里它自己的专节),执行者看过再采纳;
> ③ **能只读就只读**:不用它写文件就用 `-s read-only`,让它把结论放在最终回复里;不用它连 EDA 自己拉数据,就别开 `network_access`。

#### 9.1.2 向**运行中**的会话插话

```bash
cd "<工作目录>" && cat 插话.txt | codex exec resume --last \
  -c 'sandbox_workspace_write.network_access=true' -
```

- `resume --last` 接上最近一个会话(**包括正在跑的**),不用等它跑完。
- ⚠️ `resume` **不吃** `-s` / `-C` / `--skip-git-repo-check` / `--color`(从原会话继承,再传会报错)。
- ⚠️ `resume` 的信任校验看**shell 当前目录**,不继承原会话的 `-C` → **先 `cd` 到受信任目录再执行**。
- ⚠️ 插话里必须写明「**仅并入上下文,不要单独写文档**」,否则会和主流程双写同一文件互相覆盖。

#### 9.1.3 后台跑 + 怎么判断"跑完了" ⚠️

一轮完整审查 **10~20 分钟 / 30~50 万 token**,必须放后台。但:

**🔴 不要靠输出文件判断** —— 管道到 `tail` 会缓冲,**输出文件全程 0 字节**,看着像没跑。
也不要只信"完成通知"(实测 worker 可能还在后台干活)。

**正解:轮询产物**,等它要写的那个章节标题出现:

```bash
for i in $(seq 1 58); do
  if grep -q "^## <审查方要写的章节标题>" "<项目文档>.md"; then echo "已出现"; break; fi
  sleep 10
done
```

**产物才是真信号。** `tasklist | grep -ci codex` 能看进程数(一次会话约 5 个),
但**进程还在 ≠ 没写完**,反之亦然。

#### 9.1.4 四个必踩的坑

1. **找不到命令 / exit 127** = 入口变了(升级或换了安装方式)。`codex --version` 现查,见工具手册 §6.1。
2. **中文乱码** = 命令行内联了中文,或输入没按 UTF-8 读。改成 UTF-8 文件 + 管道(写法见工具手册 §6.1)。
3. **连不上 EDA** = 忘了 `network_access=true`,或 Bridge 没起。**会话重启后 Bridge 不一定还在**,按工具手册 §0 先扫端口。
4. **"完成通知"不等于进程真死** —— 见 §9.1.3,以产物为准。

### 9.2 协作协议

**文档分工(照抄)**

```
<本仓库>/docs/                    ← 四份手册(本文、工具手册、坑档案、PCB操作手册),两个 AI 共用,只读引用
<项目根>/
├── project.json                  ← 脚本用的项目配置(工具手册 §2.14)
├── <板名>-设计与进展.md           ← 项目文档,每块板一份。决策 + 踩坑 + 必核/必测清单 + 双方审查专节
├── _存档_设计与进展-全量...md     ← 冻结后生成:审查原文整体搬来这里(§12.3)
└── AI直连通信日志.md(可选)        ← 给人看的。每次直连后追加"消息摘要 + 对方回复摘要"
```

- 跨项目方法论 → 本手册;**项目独有的决策/板级坑 → 项目文档**;电路细节 → **开工程读,不进文档**。
- **审查结论写自己的专节**;要改对方写的内容,先提出来,不要直接改。
- 审查专节**只在评审期存在**——冻结后按 §12.3 压成一张表并移入存档。

**共享文档写入纪律(血的教训)**
- **动笔前重读当前版 + 记 SHA256**。
- **只做锚定增量编辑,禁止整文件重写**(用户明示除外,且必须先存档旧版)。
- **锚点失败即停**,不要"猜个地方插进去"。
- 写完复读 diff。

**单一执行者**:同一文档、同一时刻**只有一个 AI 能写**,另一个只读。换手前存盘并标注状态。
🚨 **用户在 GUI 里活跃编辑时,AI 对同一文档禁写**(§1-3)。

### 9.3 消息怎么写(模板)

直连消息只做两件事:**指路** + **提要求**。事实和结论一律落文档。

```
【角色】本轮你是审查者(只读),我是执行者。
【范围】只审 <板名> 的 <页/模块>,其它页不要动。
【基准】网表 <文件名>,SHA256 <前16位>;项目文档 <路径> §<章节>。
【我已做】<一句话>
【请你查】
  1. <具体问题>
  2. <具体问题>
【输出去处】结论写进 <单独的结论文件>,或 <项目文档> 里你自己的「§N 审查方第X轮审查」新章节,
           清单项标注 [必须改] / [必须核] / [建议] 三级。
【红线】不要执行任何 EDA 写操作(写接口清单见工具手册 §6.2:create/delete/modify、done()、save、importChanges 全禁);
       只读接口可用;不要碰 <某某>;不要改 §0~§N(已定稿部分)。
【收敛判定】若没有 [必须改] 项,请明确写一句"本轮未发现 [必须改] 项,可以冻结";
           若还有,逐条给出**具体改法**(值/料号/接法)。**不要为了凑数把 [建议] 升格。**
```

**要点**
- **范围必须锁死**,否则它会顺手"帮你优化"别的地方。
- 三级分类:`[必须改]`=硬伤 ｜ `[必须核]`=要人确认的疑点 ｜ `[建议]`=可选。人只需要看前两级。
- 拿不准的技术决策 → 双方都列「**待用户决策**」,**不擅自定**。
- 🔴 **【收敛判定】那两句必须每轮都带上**(原因见 §9.5.3)。
- **做从零全审那一轮**,【范围】里要写死:「**不要只看我改过的地方**,把整份图当第一次看到,
  逐个器件、逐条网络、逐个芯片的数据手册必需项过一遍」。判据是"**板子做出来能不能工作**",
  不是"网表干不干净"(原因见 §9.5.1)。

### 9.4 收敛后要产出什么

- **冻结版网表 + SHA-256**(存成 `FREEZE-<日期>-<板名>.enet`)
- **首板必测清单**:把历轮所有 `[必须核]` 合并去重,每项写清
  `测什么 / 条件 / 合格判据 / 负责人 / 日期`。**不能只写"已测试正常"。**
- **冻结 ≠ 免测**(详见 §9.5.6)。

### 9.5 🔴 收敛方法论(最值钱的一节)

> **核心结论:增量审查会漏,必须周期性做从零全审。**

#### 9.5.1 🔴 增量审查 vs 从零全审

前三轮都是**增量审查**("我改了这些,你看看"),每轮都过。第四轮用户说"隐约觉得还有问题",
改成**从零全审**("把两块板当第一次看到,逐个 IC 对数据手册过一遍")——**一次挖出 6 项必须改**,
其中两项是致命的,而且**从第一天就存在**、扛过了前三轮。

**为什么增量审查抓不到**:它只看 diff。而"从来没接对过"的东西不在任何一次 diff 里。

**规矩**:
- 每完成一个大阶段(整份原理图画完、大改之后),**必须做一次从零全审**,不看 diff。
- 全审的提示词要写死:「**不要只看我改过的地方**,逐个器件、逐条网络、逐个芯片的数据手册必需项过一遍」。
- 判据不是"网表干不干净",而是"**这块板做出来能不能正常工作、会不会烧**"。

#### 9.5.1-b 实证追加(2026-07-31,某板,从第五轮全审算起共 11 轮)

前四轮增量审查全过。第五轮改从零全审,**一次抓出「防反接 P-MOS 源漏接反」——从第一天就在**。
后果不是"板子不启动",而是反接时 P-MOS 体二极管被正偏、负压绕过已关断的 MOS 灌进后级,
**烧有极性电解电容和后级的几颗 IC**。

**三个数字值得记住:**

| 现象 | 数字 |
|---|---|
| 从零全审比增量审查多抓到的硬伤 | 防反接 MOS 方向 + 三处能力边界,**都不在任何一次 diff 里** |
| 修复动作自己引入的新硬伤 | 有一轮的硬伤是上一轮修复时把同一颗芯片的两个引脚画混了;另一轮的 5 项**100%** 是修复引入的 |
| 收敛需要的轮数 | 电气 2 轮,**文档 9 轮** |

🔴 **最反直觉的一条:文档收敛比电气收敛慢 4 倍。**
原因是网表审查抓不到文档错误 —— 防反接 MOS 方向、端子极性、布局图功率链这三件,
**DRC、不变量审计、网表全部放行**。而 PCB 是照文档布的。

**由此新增一条规矩:**
> **凡是"给人照着做"的段落(布局指令、接法图、选型表、引脚表),
> 必须逐条对着冻结网表核一遍,并且要单独作为一轮审查目标。**
> 判据不是"写得对不对",而是"**照它做出来的板子能不能工作**"。
>
> 典型高发区(本次全部中招):
> ① 电源功率链被套写成一条 `输入电容—IC—电感` 串联链(Buck/Boost/同步 Buck 是**两状态两条路径**);
> ② 旧版本的器件数/通道数/阻容值留在**现行段**而不是历史段;
> ③ 参考板的**同名位号**被当成本板位号;
> ④ 实测值与设定值混写(如把实测电流和检流电阻设定的满量程电流混成一个数)。

#### 9.5.1-c 「自检通过」的可信度取决于自检本身有没有被检验

2026-07-31 实证:PCB 侧一条"尚未布线才允许移动器件"的安全断言,
因为字段名写错(`layerId` vs `layer`)而**恒真放行**,全程无人察觉 ——
包括我自己每轮都在报告"铜线 0,可以安全移动"。

这和 §9.5.1 的教训同源:**增量审查看不见"从来就没对过"的东西**。
自检脚本、不变量、门禁断言,**本身也是"从来没被审过"的代码**。

**规矩**:
- 断言写完,**先构造一个应当命中的样本让它报警**,确认它会 fail;不会 fail 的断言等于没有。
- 交叉审查时,把**自检脚本本身**也交给对方看一眼,而不只是交自检的结论。

##### 同日再犯一次,把规矩补全成**双向**

上面这条只写了"反向自测"(应报警的样本),当天下午就被打脸:
我写了个走线连通性检查器,拿一条**未布线**的网做自测 —— 它正确报了"断开",自测通过。
然后它把**十条已经布通的网也全判成断开**,我差点据此告诉用户"你的返工有断头"。

根因是漏了一条边(union-find 里忘了把**同一段走线的两个端点**连起来),
于是每条线都被当成两个孤立点 —— **一个"恒报警"的检查器**。
而"恒报警"完美通过任何反向自测。

> 🔴 **门禁/检查器必须双向自测,缺一不可:**
> - **反向**:一个**应当被拦下**的样本 → 必须报警。防的是"恒放行"(如《PCB操作手册》§4 错误档案 E9 的 `layerId`)。
> - **正向**:一个**应当被放行**的样本 → 必须通过。防的是"恒报警"。
>
> 正向样本要挑**已知为真、且与被测对象同类**的 —— 我这次用的是
> 「用户亲手布通、且我此前已验证过的两条网」,一跑就现原形。
>
> **判据**:自测样本没凑齐两个方向之前,检查器的输出不许写进报告、更不许告诉用户。

#### 9.5.1-d 🔴🔴 **审查的最大盲区是「板子的边界」** —— 四个板杀错误全在这条线上

2026-07-31,最后一轮审查判定「可以冻结」之后,用户查资料发现**某个标准外接件的端子线序整个倒序**。
把这块板迄今的板杀级错误排一排,规律刺眼:

| # | 错误 | 谁发现的 | 网表自洽? | DRC / 不变量 / 交叉审查 |
|---|---|---|---|---|
| 1 | 输出端子极性写反 | **实物插上不工作** | ✅ | 全部放行 |
| 2 | 防反接 P-MOS 源漏接反 | Codex 从零全审 | ✅ | 全部放行 |
| 3 | **标准外接件的端子线序倒序** | **用户查公开标准** | ✅ | 全部放行(11 轮) |
| 4 | 安全断言字段名写错而恒真 | 我自己复盘 | — | 无人审过脚本 |

前三条的共同点:**错的不是设计内部,是设计与外部实物的对接关系。**
网表里两端都接着东西、成员数正常、没有单脚网 —— **一切检查都看不见它**,
因为所有自动检查的问句都是"设计内部一致吗",而没有一个问"它对得上外面那个东西吗"。

**规矩(硬):**

> **凡是跨出板子边界的引脚映射** —— 连接器线序、线缆颜色、对接件脚位、
> 外部模块针脚定义、机械件安装孔 —— **必须落到三种证据之一,并在文档里写明是哪一种**:
> ① **公开标准原文**;② **数据手册的引脚图**;③ **实物实测**。
> 三样都没有,就老实标 `[未核实]`,并进首板必测清单。

**配套的一条反面规矩,同等重要:**

> 🔴 **不许把口头描述写成"权威来源"。**
> 我当初写的是「线序(用户按实物给出,**唯一权威来源**)」——
> 这行字比错误本身更有害:它让后来每一个看到的人(包括 11 轮审查)
> 都认为这条已经定论、不必再查。**文档里的确定性措辞是技术债,
> 措辞强度必须匹配证据强度。**
>
> 附带的讽刺:同一节的另一条已经引用了这个外接件的公开规范讨论上拉电压,
> 却没顺手看同一份规范的引脚定义。**查了手册的一半,比没查更危险** ——
> 因为它留下了"查过了"的痕迹。

**给审查方的提示词要加一句**(否则对方也只会审内部一致性):

> 「除了内部一致性,请逐个**对外接口**(连接器、线缆、对接模块)核对其脚位定义
> 是否有公开标准或数据手册支撑;凡是只有文字描述、没有出处的,一律列为 `[必须核]`。」

#### 9.5.1-e 🔴 首板调试:先洗板、先烧固件,再开始测量

2026-08-02 某板首板,一整天的"幽灵故障"最终归结为两个**与设计无关**的因素:

| 真因 | 症状 | 为什么难查 |
|---|---|---|
| **助焊剂残留漏电** | USB 设备不枚举、I2C 器件"缺失"、读数飘忽 | 只打击**高阻节点**(分压、晶振内部 MΩ 反馈、I2C 上拉);低阻的电源走线一切正常,**量电源永远"没问题"** |
| **空片没有固件** | USB 反复枚举/掉线 | 空片不断重试引导,每次重试 USB 重新枚举,和硬件故障无法区分 |

**规矩:新板到手的固定开场是「洗板 → 烧固件 → 才开始测量」。**
在一块又脏又空的板子上做的所有测量,**前提都不成立**;基于它的推理越缜密,错得越远。

#### 9.5.1-f 🔴 多因素故障:找到一个真因 ≠ 找到全部真因

同一轮里我犯了两次方向相反的错:先用「空片」解释全部现象,后来发现清洗有效,
又用「助焊剂」推翻它并解释全部。**实际是两个独立因素各管一部分症状。**

> **一个新解释能覆盖 70% 的现象时,最危险的动作是拿它去推翻覆盖 40% 的旧解释。**
> 正确做法是问:「**剩下那 30%,它解释得了吗?**」——解释不了,就说明还有第二个因素。

配套的三条(同一轮实证):

- **一手资料优先于二手资料。** 两份开源参考图互相矛盾时,回到数据手册,而不是选最新看到的那份。
  本轮因一张标了 NC 的参考图推翻了手册的明文 `required`,来回翻烙饼两次。
- **每个读数必须带状态标签。** `V(检测脚) = 0.09V @USB拔出` 与 `@USB插入` 是两回事 —— 因"没说清在哪个状态下测"绕路四次。
- **同型号样品同时在场时,先用唯一标识锁定对象**(本轮用 MCU 的烧录 MAC)。
  出现过"拆掉某器件就好了"、实为插错板的误判,差点写成设计缺陷。

#### 9.5.2 只有全审才找得到的问题类型(检查清单)

这些在网表上**完全"正常"**——两个成员、不是单脚网、不是死链、DRC 全绿:

0. 🔴 **对外接口的脚位映射错误**(连接器线序、极性、线色)——见 §9.5.1-d,**迄今命中率最高的一类**
1. **开漏网络缺上拉**(I2C / INT / FAULT / DIAG)——物理上永远拉不高(见 §3.5-N)
2. **反馈分压算错** —— 电源输出电压不对,但网表拓扑完全正确
3. **无源器件额定不够** —— 电感的温升电流、连接器的额定电流、电容的耐压
4. **引脚功能用错** —— 接的脚不具备所需的复用功能(如把模拟采样接到没有运放输入能力的脚)
5. **未上电域的反向注入** —— 电源被切断的一侧,信号仍被另一侧驱动,经 ESD 二极管反灌
6. **双向脚被推挽驱动** —— 如复位脚,内部也会拉低,与外部驱动对顶
7. **驱动能力与负载不匹配** —— 逻辑门直驱大电容(额定 50pF 却接了 100nF)
8. **停产料 / 不推荐新设计**

#### 9.5.3 收敛判据(不这样写会无限迭代)

审查提示词里必须写:

> - 若**没有必须改的项**,请**明确写一句"本轮未发现 [必须改] 项,可以冻结"**。
> - **不要为了凑数把 [建议] 升格。**
> - 若还有硬伤,逐条写清并给出**具体改法**(值 / 料号 / 接法)。

**"给具体改法"这条特别重要** —— 只说"这里有风险"会导致来回扯皮;
给到"换成 XX 料号、阻值改成 XX、这样接"才能一轮闭环。

#### 9.5.4 平行独立全审(交叉印证)

条件允许时,**两个审查方(两个子代理,或子代理 + 第二个 AI)同时各做一遍全审、互不知情**,然后比对:

- **两边独立命中同一条** → 置信度极高,直接改。
- **只有一边命中** → 也大概率是真的(实证:双方各自都抓到了对方漏的 2~3 条)。
- 比对表本身要入档,它比结论更有价值。

#### 9.5.5 撤回误报也要记录

审查者会误报。**撤回时要把"为什么当时以为是问题、后来凭什么否掉"写清楚**——
否则下一轮/下一个人会重新报一遍。

> 实证:一条限流电阻被判"余量太小、电流不可控",后来翻出用户**已实物验证板子**的导出网表,
> 发现新板与它逐点一致。**方法论见 §3.5-M:报警之前先查参考设计。**

#### 9.5.6 冻结的含义

"原理图冻结" = **连接关系与器件级硬门禁收敛**,**不等于首板免测**。
冻结时必须同时产出一份**首板必测清单**,把历轮所有"必须核"合并去重,每项写清:

```
测什么 / 条件 / 合格判据 / 负责人 / 日期
```

不能只写"已测试正常"。

### 9.7 🔴 推荐(默认):单会话子代理红队 + 对辩(2026-10-07 实证)

**什么时候用**:需要独立审查时,默认用它,不需要第二个 AI。§9.1~§9.6 拉 Codex 等第二个 AI 交叉审查是备用;两者可叠加:子代理先审一轮,再交第二个 AI 做最后一道。
画完或改完一版、准备冻结或投板前,**主动向用户提议**「要不要开子代理审一轮」,并说清大概成本(见下文「成效与成本」)。

**做法一句话**:作者自审的同时,在本会话里开两个只读子代理独立审,结论回来后逐条对辩。

**怎么开**
- 分工:一个审电气(网表、规格书、固件假设、BOM),一个审图面与文档(注释对网表、版式、项目文档里的数字)。
- 只给事实和文件路径(冻结网表、上一版网表、页源码、渲染图、项目文档、手册、固件),**不给作者的结论**;明说「假设作者一定犯了错」;
  要求每条带证据、严重度、置信度,并区分本次引入和旧版遗留。
- 红线:只读;不碰 EDA 桥接(执行者也在用);不改项目文件。有的环境不让子代理写报告文件,就让它把全文放在最终回复里。

**怎么辩**
- 作者逐条回应:接受的直接改;有分歧的,把作者方案、用户决定、具体落图发回去,要求对方攻击作者方案,并和它自己的方案逐项比。
  实测有审查员比完撤回了自己的推荐:「ESD 阵列 VBUS 脚接板上 5V」在 TVS 短路失效时会拖死整板 5V,用户选的「串二极管隔离」更好(§11.5)。
- 改完让两位再复核一轮,只查「改到位没有、改出新问题没有」。

**成效与成本**
- 两位审出作者漏掉的「必须改」3 条:一个符号上叫 NC、规格书却要求接地的芯片引脚(§3.2),一条写反的接口线序注释(板杀级),一个下不了单的料号(§5.2);另有 20 多处图面和文档问题。
  作者和电气审查员各自独立发现了同一个 VBUS 倒灌问题(§11.5),互相印证。
- 每位每轮约 50~70 万 token、10~40 分钟;第二轮电气零新增「必须改」,图面又挑出 8 处版面细节。
- 引用规格书要读原文:WebFetch 的摘要模型在 ST 手册上编出一句不存在的「VBUS 脚悬空可降低电容」,改用本地解析 PDF 原文才对上。

## 10. 可复用脚本清单与不变量

> 旧 CLI 时代这里列的是让新项目照建的 7 个脚本(`build_page.py`、`connect_chunked.py`、`swap_conn.py` 等),**已随旧 CLI 作废,不用再建**。
> 新工具下的现成脚本在本仓库 `tools/`,用法和各自编码了哪些坑见工具手册 §2.14;项目根放一个 `project.json` 就能用,**不用拷脚本**。
> 下表右列的不变量与工具无关:用现成脚本时拿它核对,自己写或改脚本时照抄。

| 职责 | 本仓库现成脚本 | 关键不变量 |
|---|---|---|
| 建页、放件、补 Value | `v2_rows.py`(行式建图)、`v2_add_parts.py`(按立创编号批量加件并接线) | 坐标网格对齐、库件解析成功、三重绑定齐;补 Value 前做**引用键红线检查**(含 `Footprint/Symbol/3D Model/Device` 就拦截不写) |
| 接线、改网 | `v2_wire_pins.py`(给已有器件的引脚接短桩 + 符号)、`v2_route_pin.py`(往排满的页里找零相交路径) | 改前后网表 diff 只允许预期的网变化;以**重新导出的网表**为终审,不信过程回读 |
| 换型 | `v2_swap_part.py`(原地换件;删除后**不单独读回**,只靠改前后网表护栏) | 删除后必须读回确认真的没了(§3.5-G,用这个脚本时自己补一次读回);只允许本次涉及的网变化;收尾**逐脚核对** |
| 全工程审计 | `v2_geom_audit.py`(几何三查) + `v2_refreeze.py`(总门禁:几何 → 网表语义 → 与冻结 diff → DRC) | 见下方"不变量式校验";`v2_refreeze.py` 已查单脚网和 Value 空,另两条要自己补 |
| PCB 分组打包(§8) | 暂无现成脚本 | 只改 x/y 不改 rotation;覆盖性断言(漏件/重复归组即中止) |

### 10.1 🔴 "不变量式校验"的价值

审计脚本里最值钱的不是"检查我这次改对没有",而是**永远成立的不变量**。它们不挑失败原因。

必备的四条:

| 不变量 | 抓什么 |
|---|---|
| **同板同料号 → Value 必须唯一** | 跨页脚本按位号误伤、换件中途失败留下的半成品 |
| **单脚网 = 0**(白名单外) | "两边一致地断着"、复制进来的死端子 |
| **同页同坐标器件数 = 0** | 静默短路、delete 失败导致的重叠重复件 |
| **所有件 Value 非空** | ⚠️ 判据不能是"显示名含 `{Value}` 才查" —— 显示名走 `={Manufacturer Part}` 的件(IC/连接器/PTC/MOS)一样要有 Value,否则 BOM 那列是空的 |

> 实证:"同板同料号 Value 唯一"这条本来是为防"跨页误伤"加的,结果第一次真正抓到的是
> **换件中途失败**(Value 已改、器件还是旧料号)。**这就是不变量的价值——它不需要预知失败模式。**

### 10.2 NC 白名单要会过期

有意悬空的引脚要白名单化,但**白名单会掩盖将来的断线**。
> 实证:三个引脚后来接上了,白名单没同步,等于给它们开了永久豁免。

**规矩**:每次全审都要反查白名单里的项**是否仍然真的无网**,已连接的立刻移出。
更好的做法是把白名单做成"只允许当前确实无网的项"的自动生成清单。

## 11. ESP32-S3 主控板专章

> 只在做 ESP32-S3 类主控板时看。其它芯片可跳过。

### 11.1 引脚红线(WROOM-1-N16R8)

| 引脚 | 情况 |
|---|---|
| IO26~IO32 | 模块内部 SPI Flash **占用,固件永不配置** |
| IO33~IO37 | 模块内部 **OPI PSRAM** 占用。板上 NC 也不许碰,碰了 flash/PSRAM 就废 |
| IO0 / IO3 / IO45 / IO46 | **strapping 脚**,外部上下拉会影响启动模式。`IO46` 上电必须为低(常用作"输出使能"的安全态) |
| IO19 / IO20 | 原生 USB。用作 USB CDC 控制台时不可他用 |
| IO43 / IO44 | UART0,留作调试口 |

> ⚠️ **温度等级**(2026-10-07):WROOM-1 规格书 §1.1 —— R8 / R16V 系列(含 N16R8)工作环境 −40~65°C,其它型号 −40~85°C。
> 装在密闭、偏热环境里的板子要算这一条;固件不用 PSRAM 的话,N16 是 85°C 的选项。

### 11.2 固件侧五个已验证的坑

1. 🚨 **USB CDC 写阻塞会挂死整个主循环**(实证 3 次)
   `ARDUINO_USB_CDC_ON_BOOT=1` 下,**HWCDC 在 TX 缓冲满时默认阻塞**等主机排空。
   USB 线碰松或上位机不再读 → 下一次 `Serial.printf` **永不返回** → 主循环停摆
   (COM 口仍正常枚举,极具迷惑性)。
   **必修**:`Serial.setTxTimeoutMs(0)` 放在 setup 最早处。
   **兜底**:主循环加任务看门狗(30s);长时间占住 loop 的地方要自己喂狗(OTA 下载循环等)。
2. **`WiFi.setSleep(false)` 与蓝牙共存 = 上电循环复位**
   backtrace 是 `NimBLEDevice::init → esp_bt_controller_enable → coex_enable → abort`。改用 `WIFI_PS_MIN_MODEM`。
3. **espota 被 Windows 防火墙拦** —— WiFi 被归类成"公用网络"、Python 没有入站规则,两样都得处理才能通。
   ⚠️ 这是系统安全设置,由用户自己决定、自己改:只在**可信的局域网**里把网络改成"专用";入站规则**只放行对应程序和 OTA 端口**,用完删掉;不想动防火墙就改用 USB 烧录。
4. **已出货、靠 OTA 升级的设备,分区表和 NVS 不许动** —— 要 OTA 就得有 app0/app1 + otadata 双槽;
   已出货设备的 `nvs` 偏移 / 大小(Arduino-ESP32 默认分区表是 0x9000 / 0x5000)新固件必须沿用,改了就读不到现场数据。新项目首版自己定,定了就别再动。
   🚨 **生产板严禁"全片擦除"**,会连 WiFi 凭据、计数这类现场数据一起抹掉。
5. **flash_mode 别信默认** —— 实测某 ESP32-C3 小板按默认 `qio` 起不来,改 `dio` 才行。这是那块板的实测,不是普适规则:
   先查模组 / Flash 规格书支持哪种模式;已出货设备做 OTA 兼容时,新固件的 flash_mode 与设备上现有固件保持一致。

### 11.3 排障利器:`Saved PC` + addr2line

```bash
xtensa-esp32s3-elf-addr2line -pfiaC -e .pio/build/<env>/firmware.elf 0x420d350a
```

| 解出来落在 | 说明 |
|---|---|
| `esp_pm_impl_waiti` | **CPU 空闲等待** = 某任务阻塞在等待上(不是崩溃、不是死循环) |
| 具体业务函数 | 死循环或崩溃点 |

配合 `[boot] reset_reason=N`:9=BROWNOUT(供电)、6=TASK_WDT、4=PANIC。

### 11.4 硬件上最容易漏的一条:追清楚功率级的"许可链"

实证:某板上的一路 PWM 功率输出和另一组执行器**共用同一道许可**:
```
EN → Qa 栅 → Qa 漏 → Qb 栅 → 高边 P-MOS
```
后果:许可没给时,这路 PWM 在切一条**没电的轨**。固件不检查就会一直满占空比输出,
直到被超时保护逮住,并**误诊成负载断线**。

**通用教训**:任何"软件控制的输出",都要在文档里画清它的**电源许可链**,
并在固件里**显式前置检查**。项目文档里那句"与 XX 共用许可"当时没人当回事,上机才炸出来。

### 11.5 自供电板的原生 USB:VBUS 检测会被 D+ 上拉倒灌(2026-10-07 实证)

- **事实**:S3 没有 VBUS 脚;USB-Serial-JTAG 从 ROM 起就接上 D+ 的 1.5k 上拉(寄存器复位值 `DP_PULLUP=1`),和主机在不在无关。
- **坑**:USBLC6 这类轨到轨 ESD 阵列的 VBUS 脚,如果和 VBUS 检测分压接在同一节点,拔线时 D+ 上拉会经阵列内部 I/O→VBUS 的二极管把这个节点抬到约 2.7V,
  检测脚落在 1.6V 左右的不定区。乐鑫要求「拔线 3ms 内检测脚为逻辑低」,做不到;Type-C 源端也可能因为 VBUS 不在 vSafe0V 而不出电。
  板上有 USB Hub 芯片、MCU 挂在 Hub 下游时没这个问题:Hub 看到 VBUS 才在上行口接上拉。
- **正解**:分压直接取连接器 VBUS;ESD 阵列的 VBUS 脚经一只低漏电二极管(1N4148WS 一类;别用肖特基,高温漏电会把检测脚抬起来)从连接器 VBUS 取电,
  阵列 VBUS 脚旁加 100nF(ST 手册 Fig.17 的 C_BUS)。**别把阵列 VBUS 脚改接板上 5V**:TVS 常见失效是短路,会拖死整板 5V。
- **板子断电、主机还在**:VBUS 经分压灌进没上电的 GPIO(超 VDD+0.3)。检测脚前串 1M,注入降到微安级;脚旁加 1nF 滤噪(τ≈1ms,仍满足 3ms)。
- **固件**:检测脚必须 `INPUT`、不开内部上下拉(约 45k 的内部上下拉会完全盖过 1M);读低时撤 D+ 上拉(`USB_SERIAL_JTAG_PAD_PULL_OVERRIDE=1`、`DP_PULLUP=0`)。

### 12.3 冻结后必做:把项目文档瘦身

原理图一冻结,项目文档里就有**大半是过程而不是事实**,必须剥离,否则接手的人(或 AI)被淹在
审查流水账里,找不到真正要执行的东西。

**做法**

1. **先存档全文**(铁律:整文件重写必须先存档旧版):
   `_存档_设计与进展-全量含N轮审查原文-YYYYMMDD.md`
2. **删掉能从工程读出来的**:引脚分配表、网络成员 dump、坐标、器件清单快照。
   换成**指针**——工程 uuid、页面 uuid、冻结网表路径 + sha256、`tools/` 位置。
3. **逐轮审查原文 → 一张表**:每轮「基准网表 / 找到的 `[必须改]` / 处置」。
   `[建议]` 和被驳回的项不进表(它们在存档里)。
4. **把埋在审查章里的清单提到顶层**:必核清单、**首板必测清单**、固件侧硬要求。
   这三样是验收物,不能藏在第三十章的某个小节里。
5. **踩坑单列一章**,并把其中**通用**的那几条上交到手册(工具坑进《坑档案》,电路 / 流程类进本文 §4、§9)——项目文档只留板级特有的。
6. 正文里遗留的 `§NN` 旧章节号**不要逐条改**(改不干净还会引错),
   在文首声明一句「形如 §NN 的引用指存档全文」即可。

**保留清单(一条都不能丢)**:接手指引 / 关键选型与依据 / 电源架构 / **设计决策记录** /
必核清单 / 必测清单 / 固件侧硬要求 / 踩坑与解决 / 工具脚本 / 待办 / 冻结记录(含 sha256)。

> 实测(某项目,2026-07-29):七轮审查原文 + 七轮修复记录占全文 **72%**。
